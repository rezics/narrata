## 结果

[决定 8](../../../../docs/product/decisions.md#8-存储契约保持窄) 的后端契约成为代码：一个只认字节、摘要与键
的存储后端 trait，两个实现（内存参考、按行读写的 SQLite），以及任何后端都要通过的一致性套件、
故障注入包装器和计数包装器。这是之后把 `narrata-store` 的领域逻辑（Effect 账本、目录、复合存档、
pin、GC、完整性、bundle 闭包）改写为"在契约之上只实现一次"的基础；那一步是下一个任务，**不在本
任务内**。

先读：[存储与存档契约](../../../../docs/contracts/storage-and-saves.md)、
[调研报告的存储一节](../../../../docs/research/2026-10-04-engine-core-and-storage/report.md#最小存储契约)
与它的 "改什么" 表、ADR 0006（存储边界）与 ADR 0011（节点栈独立）。现有领域接口
`crates/narrata-store/src/store.rs:310-369`（`SaveStore`、`CommitTransaction`、`RefRevision`）、
`memory.rs` 与 `crates/narrata-store-sqlite/src/lib.rs` 只作为"契约之上必须能实现什么"的参照：
效果账本的 claim/lease/fence、目录头与复合存档的 CAS、输入幂等索引、pin、带宽限期的 GC
（`inserted_at`）、完整性扫描，以及 `tests/model.rs`、`tests/faults_gc.rs` 的断言，都必须能只用
本契约的原语写出来。写 ADR 前逐项核对这一点。

## 已定的方向（理由写进 ADR）

- **位置与依赖。** 新 crate `packages/narrata/kernel/crates/narrata-storage`（契约、内存后端、
  `testing` feature 下的套件与包装器）和 `packages/narrata/kernel/crates/narrata-storage-sqlite`。
  不依赖 `narrata-core` 或 `narrata-store`，这样节点栈也能用（ADR 0011）；只用 `thiserror`，
  套件可用 `proptest`（可选依赖）。加入根 `Cargo.toml` 的 workspace 成员，`[lints] workspace = true`。
  `narrata-storage` 必须能为 `wasm32-unknown-unknown` 编译（浏览器后端以后在它之上）。
- **同步 trait。** 嵌入式与 Wasm 内都是同步调用；异步宿主（IndexedDB、网络）以后通过"引擎产出
  批次、宿主落盘后确认"的协议接入，而不是让 trait 变成 async。ADR 写明这个取舍。
- **两类数据。** 不可变对象：调用方给出 32 字节摘要和字节，`put_if_absent` 幂等；后端不计算也不
  信任摘要，读取后由引擎重新校验。可变键：`(键空间, 键字节) → (值字节, 修订号)`，按键字节有序、
  可分页扫描。引用与引擎维护的索引都是键；是否把"带 CAS 的引用"与"无前置条件的索引键"统一成
  一种键、只靠批次里每个操作的前置条件区分，由你按实现的简洁程度决定。修订号必须避免 ABA
  （删除后重建不能复用旧修订号；考虑全库单调的版本号）。
- **原子批次。** 一个批次包含对象写入、对象删除（只供 GC 使用）、键的写入与删除，每个键操作可带
  前置条件（不存在 / 等于某修订号 / 只检查不写）；任一前置条件失败则整批无效果，错误指明哪个键
  和它的当前修订。
- **有界读取。** 按摘要批量读对象；读单个键；按键空间与前缀、带游标、有上限的有序扫描；对象只能
  分页扫描（GC 清扫与完整性检查用），没有一次返回全部的枚举。
- **能力声明。** 至少：多键原子性、并发写者、持久性（持久 / 可被驱逐 / 仅内存）、单值、单批与单次
  扫描上限。超限的批次被拒绝而不是部分写入。不支持多键原子性的后端只能单写者；本任务不实现这类
  后端，只把语义写进 ADR 与类型。
- **错误。** 区分前置条件冲突、超限、可重试（Busy）、满、I/O 与损坏。写明哪些错误意味着"结果
  未知"（批次可能已生效），引擎以后据此重读而不是盲目重试。

## 交付

1. `docs/adr/0012-<名字>.md`：契约、上述取舍与理由、SQLite 表结构与 schema 版本、"`SaveStore` 的
   每类操作如何映射到原语"的对照表（这张表是下一个任务的设计输入），以及明确不做的东西。键空间
   的具体布局（哪些前缀存什么）属于下一个任务的引擎 ADR，这里只定义机制。
2. `narrata-storage`：trait、类型、`MemoryBackend`（行为参考，实现尽量直白）。
3. `testing` feature：
   - 一致性套件：任何后端用一个工厂（新建；持久后端另给"重新打开"）调用即可运行。覆盖对象幂等与
     删除、键 CAS 的每种前置条件、批次原子性（第 k 个操作失败时前 k-1 个不可见）、扫描的顺序、
     前缀、游标续读与上限、能力上限的拒绝、重新打开后的持久性、声明并发写者的后端在两个句柄间
     竞争同一 CAS 时恰有一个成功；再加一个随机操作序列对独立简单模型的属性测试（参照
     `crates/narrata-store/tests/model.rs`）。
   - 故障注入包装器：按确定的计划让第 N 次调用在执行前失败（无效果）或执行后报错（已生效但报告
     失败，即"结果未知"），以及读失败。
   - 计数包装器：按原语计数调用次数、返回的对象数与扫描的条目数，供以后断言"加载单个提交不触发
     全对象枚举"。
4. `narrata-storage-sqlite`：按行读写；每个批次一个 `BEGIN IMMEDIATE` 事务；WAL、
   `synchronous=FULL`、busy timeout；声明并发写者；SQLite 错误映射到契约错误。通过全部一致性
   套件（含重新打开与双连接竞争）。加一个小的 criterion 基准：在已有 1K 与 100K 个键/对象的库上
   应用一个批次、读一个键、扫描一页，证明单次操作代价不随库大小线性增长。
5. 收缩 [存储与存档契约](../../../../docs/contracts/storage-and-saves.md) 的"后端契约"一节为指向 crate 与
   ADR 的几句话；当前缺口中已解决的不要删，它们仍属于下一个任务。

## 不要做

不改 `crates/**`（`narrata-store`、`narrata-store-sqlite`、协议引擎都留给后续任务）；不做
IndexedDB、OPFS、PostgreSQL、JSON 目录或对象存储后端；不做 async；不定义领域键布局；不写冻结
语料（新 SQLite 文件格式的兼容证据在引擎任务确定键布局后再定，ADR 里写明这一计划）。
