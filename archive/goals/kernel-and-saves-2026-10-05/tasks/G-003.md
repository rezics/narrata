## 结果

[决定 11](../../../../docs/product/decisions.md#11-节点组合模型是长期内核的语义基础) 的第一步：可靠执行机制
中与领域无关的底层——摘要分帧、ADR 0003 的规范 CBOR 读写、受检解码、对象封套与对象 ID、身份类型
的定义方式——搬进新 crate `packages/narrata/kernel/crates/narrata-kernel`，让节点栈和以后的领域包
不依赖 `narrata-core` 也能使用它们（ADR 0011 要求节点栈不依赖旧 core）。这是**逐字节不变的搬移**：
`fixtures/compat/stage5-v0` 与 `fixtures/codec` 的每个摘要、每个字节都不变。

现状（只读参考）：

- `crates/narrata-core/src/codec/canonical.rs` 的 `CborWriter`/`CborReader` 是 `pub(crate)`；
  `narrata-store/src/codec.rs` 因此复制了一份私有的 `Writer`/`Reader`。
- `codec/digest.rs`：`digest_bytes(domain, schema, payload)` 与 `sha256`。
- `codec/envelope.rs`：56 字节封套头；`ObjectKind` 是封闭枚举（码 1–11），未知码被拒绝。
- `narrata-store/src/object.rs:122-132`：`object_id = SHA-256("narrata-object\0" ‖ kind_be16 ‖
  schema_be16 ‖ payload)`。
- `identity/`：`authored_id!`/`derived_id!` 宏与 `text::parse` 都不公开，新 ID 类型只能加在 core 里。
- 每个 schema 解码器各自"解码后重新编码并比较"（如 `program/wire.rs:93`）。

## 交付

1. `narrata-kernel`（依赖只有 `sha2`、`hex`、`thiserror`；`[lints] workspace = true`；能为
   `wasm32-unknown-unknown` 编译），公开：
   - 摘要分帧 `digest_bytes` 与 `sha256`，算法与现在完全相同；
   - ADR 0003 的规范 CBOR 写入器与读取器（最小头、定长、拒绝浮点与 tag 等现有规则），以及
     一个受检解码帮助：给定解码函数与编码函数，解码后要求重新编码得到相同字节，带深度/长度上限；
   - 以 `u16` 种类码表示的对象封套读写与 `object_id(kind_code, schema, payload)`。哪些种类码合法
     由领域决定：`narrata-core` 保留封闭的 `ObjectKind`（码 1–11，未知码照旧拒绝），在 kernel
     之上做映射；
   - 定义 16 字节作者身份与 32 字节派生身份类型的导出宏和文本形式（`prefix:hex`）解析，使
     其他 crate 能定义自己的 ID 类型，文本形式与现有类型一致。
2. `narrata-core` 依赖 `narrata-kernel` 并通过原有路径重新导出，现有调用方（store、protocol、
   ffi、wasm、cli、testkit、fuzz）不需要修改；如果某处必须改，改动保持机械且最小，列入
   OWNER CHANGES。`narrata-store/src/codec.rs` 改为使用 kernel 的读写器并删除复制的实现，
   `object.rs` 的 `object_id` 改为调用 kernel。
3. kernel 自己的单元测试：CBOR 规则的正反例（可从 core 现有测试搬过来）、摘要与对象 ID 的已知
   向量（取自 `fixtures/compat/stage5-v0/manifest.json` 与 `fixtures/codec`），以及受检解码拒绝
   非规范输入。

## 不要做

不改任何线格式或摘要；不搬 `Value`、Program、Snapshot、Flow VM、Statechart、effect、migration
（它们是领域，以后单独成包）；不重写各 schema 解码器去用新的受检解码帮助（以后触及时再换）；
不碰 `narrata-store` 除 `codec.rs`、`object.rs` 以外的文件；不改 `packages/narrata/nodes`。
另一个任务同时在 `packages/narrata/kernel/crates/narrata-storage*` 建存储契约 crate，不要碰它。
根 `Cargo.toml` 与 `Cargo.lock` 不属于任何认领：只做加入成员与依赖的最小改动，列入 OWNER CHANGES；
合并时与另一个任务的成员改动冲突是预期的。
