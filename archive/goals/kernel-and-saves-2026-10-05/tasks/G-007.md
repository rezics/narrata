## 结果

[决定 11](../../../../docs/product/decisions.md#11-节点组合模型是长期内核的语义基础) 的存档部分：提交/引用对象库
成为 kernel 的一层，任何注册的领域（旧 Flow/Statechart、节点 R2，以及以后的领域）都通过它保存、
恢复、分支、导出与导入，逻辑只有一份。

1. **抽取。** G-004 在 `narrata-store` 里写成的引擎（[ADR 0014](../../../../docs/adr/0014-save-engine-key-layout.md)）
   中与领域无关的部分搬进新 crate `packages/narrata/kernel/crates/narrata-history`（依赖
   `narrata-kernel` 与 `narrata-storage`，不依赖 `narrata-core`/`narrata-store`，能为
   `wasm32-unknown-unknown` 编译）：按种类注册表校验的对象读写（封套、摘要、种类与 schema）、
   touch 键与 `meta/graph`/`meta/sweep` 栅栏、GC（根键空间与出边由注册方提供）、完整性扫描、
   引用与 pin、子提交索引、结果未知时的重读核对、checkpoint bundle 容器与清单（描述符的种类按
   注册表检查，不再按封闭的 `ObjectKind`）。旧栈特有的部分留在 `narrata-store` 并注册进来：
   种类 1–11 的出边与语义校验（`graph.rs`、`engine/validate.rs`）、目录、归档、复合存档、输入、
   Effect 账本与 fence、目录操作、按 turn 的提交索引、`SessionCoordinator`。
2. **领域注册与通用提交。** 新领域实现一个静态 trait（不是 `dyn` 插件）：提交/状态/输入的种类码、
   `artifact_id`、状态与输入的编码和受检解码（解码时对照构件校验，是构造状态的唯一途径）。
   kernel 定义通用提交对象，CBOR `{0: artifact bstr32, 1: parent bstr32|null, 2: input ObjectId|null（仅根）,
   3: state ObjectId, 4: depth uint}`，种类码由领域给出，身份是 `object_id(kind, 1, payload)`；写入时
   检查父提交存在、同种类、同构件、`depth` = 父 + 1，状态与输入对象种类正确。会话 API（命名由你
   定）：创建、`advance(expected_head, input, step 闭包)`（同一父提交加同一输入复用已有提交，由
   `(parent, input) → commit` 索引判断；同键得到不同提交报告不确定性）、checkout、按页列出子提交、
   存档槽的保存与加载、checkpoint 导出与受检导入。kernel 从不调用领域的 step trait——`advance`
   只在转换是新的时候运行调用方给的闭包。**恢复不重放**：读引用、校验提交摘要、核对构件、受检
   解码状态；祖先在访问时校验；可选的 `verify_path` 审计（沿路径重放并比较）留给领域调用。
3. **种类码。** 1–11 旧栈；`0x0100–0x01FF` 节点栈（已与 `narrative-core` 约定：0x0100 清单、
   0x0101 程序块、0x0102 墓碑集、0x0103 名字表、0x0104 包容器、0x0110 提交、0x0111 状态、
   0x0112 输入，0x0120–0x013F 图分析）；测试领域另取一段并在 ADR 里登记。GC 遇到未注册的
   种类必须拒绝运行（否则会删除只有它不认识的提交才引用的对象），完整性扫描报告它们。

对照：`D:/rezics-repos/narrata/.temp/kernel-and-saves/kernel-history-proposal.md`（主 checkout 中 manager 的设计草稿，只读，
已发给 `narrative-core` 并被接受；它不在你的 worktree 里，下面已写明要点）。草稿认为不需要的东西：

## 约束

- `fixtures/compat/stage5-v0`、`store-sqlite-v2`、`store-layout-v1` 全部照旧通过；ADR 0014 的
  键空间编号与编码不变（这是冻结的存储格式）。通用层新增的键空间（如转换索引）取新编号。
- 通用层不复制 `narrata-store` 的代码：搬过去之后旧位置只剩注册与旧栈特有的逻辑。
- `narrata-kernel` 不改：`narrative-core` 的任务正在往它的 `src/content/**` 加内容引用类型。
  需要 kernel 新增公开项时，在 `narrata-history` 里先写，交接时提议搬移。
- 节点栈（`packages/narrata/nodes/**`）不改：接入由 `narrative-core` 在本任务合并后完成。

## 交付

1. `docs/adr/0015-<名字>.md`：两层的边界、注册 trait、通用提交格式与身份、转换索引、新键空间、
   种类码分配、恢复的信任边界（证明状态良构，不证明经由游玩可达）、GC 对未注册种类的处理，
   以及推迟的东西（节点的 Effect 账本、目录、迁移、回执、浅存档、宿主异步协议）。
2. `narrata-history` 与 `narrata-store` 的改造；store 的全部测试仍在内存与 SQLite 两个后端上通过。
3. 一个只在测试中使用的小领域（例如计数器：状态是整数，输入是增量）证明通用 API：在两个后端上
   覆盖创建、推进、去重、不确定性检测、分支、checkout、子提交分页、存档槽、无重放加载、导出与
   受检导入（篡改字节被拒绝）、GC 保留所有分支头、计数包装器断言加载读取不随深度增长。
4. 冻结语料 `fixtures/compat/kernel-history-v1/`：测试领域的一份 checkpoint bundle 与一份 SQLite
   库及清单，测试保证以后的版本能读取它们。
5. 存储契约页与时间旅行架构页中被 ADR 0015 取代的内容改为指向它。

## 不要做

不改任何旧格式字节；不接入节点栈；不改协议引擎的存储注入方式（宿主批次协议与 IndexedDB 是
下一个任务；协议引擎只做为编译所必需的最小改动）；不做浅存档；不做 async。
