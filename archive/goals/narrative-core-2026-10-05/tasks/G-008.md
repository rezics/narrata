## 结果

把 `narrata-graph`（已在 main 上）的内存输出固定为可分发、可受检读取的格式，宿主（作者视图、
REZICS 的 R9）才能使用它们。

1. **ADR 0016**：只定义本 crate 的输出，形状尽量少。
   - **瓦片**：用 `narrata-kernel` 的规范 CBOR 与信封，以 `object_id` 命名，kind code 取 ADR 0013
     为分析保留的 `0x0120–0x013F`：
     - `0x0120` 瓦片索引：各细节层级、瓦片的 object id、包围盒、簇到瓦片的映射；
     - `0x0121` 作品级瓦片；
     - `0x0122` 簇级瓦片；
     - `0x0123` 节点级瓦片。

     列是小端类型化数组，放在 CBOR byte string 中；节点 ID 是 16 字节一行的拼接列。
   - **标签表**：保留 kind code `0x0124`，形状留给 R2 适配任务。它把 `NodeId` 映射到 ADR 0013
     的 `ContentRef` 标题，与几何瓦片分开：本 crate 不依赖节点格式。
   - **语义摘要**：带版本的 JSON，含 `format_version`、入口、结局与分类、每个结局可达的簇集合、
     压缩后的瓶颈序列，以及一个留给适配器填写的 `artifact_id` 字段。用 Rust 类型生成 JSON
     Schema，放在 crate 内。
   - 写明哪些变化会改变 object id，以及读取方如何拒绝坏输入。
2. **编解码**：
   - 编码；
   - 受检解码：规范往返、列长度与元素数一致、索引越界、kind 与 schema 版本；
   - 拒绝篡改的属性测试。

   列只做整数，坐标沿用已实现的定点值。同一输入得到逐字节相同的输出（已有确定性测试，扩展到
   编码后的字节）。
3. **冻结语料** `fixtures/compat/graph-v1/`：
   - 一个小的合成图（几十个节点，覆盖环、不可达、死路、多个结局、跨簇分支）的全部瓦片、瓦片
     索引和语义摘要；
   - 带 SHA-256 的 `manifest.json`；
   - 一个测试从语料受检读取并与重新生成的字节比较。

   kernel-and-saves manager 已同意这个目录放在它的 `fixtures/**` 范围内。另外在根
   `.gitattributes` 中为它加 `-text`：该文件无人认领，作为 OWNER CHANGES 报告。
4. 基准重测：用编码后的真实字节数和 gzip 大小更新 `docs/development/benchmarks/graph-layout.md`，
   测量用的临时 `.columns` 缓冲删除。契约页 `graph-and-analysis.md` 的"交付格式"改为指向
   ADR 0016 与代码。

## 约束

- 只用最小形状满足上面的需求：不要压缩方案选项、不要可插拔编码、不要 JSON 版瓦片。
  `narrata-kernel` 改为普通依赖。
- 不依赖 `narrata-nodes`。另一个任务正在实现 R2 节点格式和 `narrata-kernel` 的 `content`
  模块，不要碰那些文件。
- 根 `Cargo.lock` 与 `.gitattributes` 无人认领：做最小修改并报告。
