## 结果

实现 [ADR 0013 §5](../../../../docs/adr/0013-r2-text-free-node-format.md)：生成式系统或宿主在运行时提出
新的选项和节点，引擎校验后把它们作为 Input 写进提交历史，回退、恢复和迁移都使用记录的结构，
从不重新生成（[决定 6](../../../../docs/product/decisions.md)）。

格式字段已在 G-005 中预留（Input 的 `propose` 变体与 Frame 的 overlay 字段号，目前解码为
`unsupported`）。按 ADR 原样实现：

- **提议请求**：JSON，不含 ID，已有节点按 `NodeId` 引用，新节点按请求内的临时键引用。它与
  记录的 `propose` Input（CBOR，已派生 ID，不含临时键与别名）分开。
- **校验**：复用编译期的段落、选择点与表达式检查（`check.rs`），不另写一套。
  - 分支目标只能是本图已有节点或同一请求中的节点。
  - 针对追加后的完整选择点与段落校验。
  - 上限：每请求 16 个选项与 16 个节点，每栈帧 256 个动态节点。
  - `proposals = true` 的选择点没有可用选项时不报 `no_actions`。
- **派生 ID**：按 §5 的摘要与遍历顺序派生，按 UUIDv8 设置版本与变体位，碰撞时拒绝。
  `decode_input` 复核派生值。
- **叠加层**：写入当前栈帧，交互停在同一选择点，之后照常 `choose`，可以选动态选项、进入动态
  节点。栈帧返回时叠加层消失。`decode_state` 校验叠加层的引用不变量（§6）。
- **view**：动态选项与静态选项一起出现在 `interaction` 中。
- **Wasm**：`propose(expected_commit, request_json)` 返回新 view。
- **示例作品**：`products/` 不在本任务内。用测试中的小作品证明即可。

## 证明

- 提议后 `choose` 动态选项，进入动态节点再返回。
- 回退到提议前的提交，再提一个不同的提议：两条分支都保留，派生 ID 不同。
- 相同父提交加相同请求，复用同一提交。
- 导出、恢复（不重放）后 view 一致；`verify_path` 能重放带提议的路径。
- 受检解码拒绝：篡改的派生 ID、悬空的叠加层引用、超限、未开放提议的选择点。
- 编码往返字节一致。
- 冻结一个带提议的会话导出到 `fixtures/compat/nodes-r2-proposals/`，带 SHA-256 的
  `manifest.json`，并加一个读取测试。冻结语料是只读的，kernel-and-saves 已同意 nodes-r2 系列
  目录；根 `.gitattributes` 加 `-text`，作为 OWNER CHANGES 报告。
- `nodes-r2` 冻结语料的字节保持不变：已有对象的编码不得变化。
