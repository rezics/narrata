## 结果

只读审计（GOAL 验收逐条对照 main）找出三处未满足，本任务补齐，不做别的。

1. **图分析可从 Wasm 调用**（结果"一套 Rust 实现可在 CLI 与 Wasm 中运行"）：
   - `narrata-nodes-wasm` 暴露发布分析，输入打包构件加可选大纲，输出瓦片索引、各级瓦片、
     标签表的 object id 与字节，以及语义摘要 JSON 和诊断；
   - 复用工具 crate 的 `publish.rs`；如果它依赖文件系统，就把纯函数部分移到能编译到 wasm32
     的位置，不复制逻辑；
   - 测试证明 Wasm 路径（`wasm32-unknown-unknown` 构建，加一个 Node 或 Playwright 调用）与
     CLI `compose` 的输出逐字节一致。
2. **Wasm 按块懒加载**：
   - Wasm 现在打开并保留整个包。增加只用清单打开的方式：缺块时返回明确的"需要块 X"，宿主
     取来块后重试，照 kernel `CacheBackend` 的 NotLoaded 模式；
   - 墓碑集也改成按需加载，打开不再需要它，只在 `lookup` 与需要它的校验时加载；
   - 测试证明首屏只需清单加首块。整包打开保留为便利路径。阅读器继续用整包，宿主侧的网络
     懒加载属于 Goal `web-and-rezics`，这里只保证 API 可用。
3. **完整的只改文字属性测试**：扩展 `tests/project.rs` 的属性测试：
   - 只改内容包文字、只改别名或改语言后，重新 compose；
   - 比较产品 `artifact_id`、每个包的源稿摘要、每个块与墓碑集的 object id、lock，以及一次
     游玩中每个提交和 State 的 ID，全部不变。
4. 在 `nodes-scale.md` 中写明：单次选择低于 1 ms 依赖宿主预取下一批可能进入的块；冷启动时
   同步加载与解码的代价单独列出。

## 约束

- 满足需求的最小实现，不加格式、不改 ADR 规定的字节。
- 根 `Cargo.lock` 与工具 crate 的 `lib.rs` 无人认领：做最小修改并报告。
