## 结果

写 `docs/adr/0023-<名称>.md`（状态 Proposed）：作者重新发布 Gamebook 后，读者的存档如何继续。
只写 ADR，不写代码。

现状：节点栈的存档绑定 `artifact_id`；结构变化产生新构件，旧存档被拒绝（`incompatible_save`）。
稳定 ID、墓碑与 `Program::lookup`（Live/Deleted/Unknown）已存在，只改文字、译本与别名不改变
摘要。kernel 有通用的 `ArtifactRegistry`、`MigrationRegistry`、`MigrationInput`、
`dry_run_migration`、`apply_migration`（[ADR 0020](../../../../docs/adr/0020-shared-effects-and-migrations.md)），
但只有旧 Stage 1–5 栈与测试计数器领域使用；节点栈只有 R1→R2 的 `r1::migrate_save`。

ADR 必须对下面每一项给出决定和理由：

1. **自动迁移。** 新构件中 ID 稳定、存档状态能通过新程序受检校验时，如何自动生成迁移
   （按[决定 3](../../../../docs/product/decisions.md#3-身份以-narrata-为权威) 的表：改文字引用、条件、
   效果、顺序与改目标节点时 ID 不变），迁移提交如何记录，与 ADR 0020 的协调器如何对接。
2. **被删除的位置。** 存档当前位置或调用栈中的节点在新构件中是墓碑时：作者声明的恢复点
   （写在哪里：源稿、发布输入，格式与版本）、有损迁移报告的内容、没有声明时的结果。
3. **重放分歧。** 决定 3 承诺"改目标节点：旧存档差异由重放分歧检测与迁移处理"：何时需要
   重放、如何检测分歧、分歧时读者看到什么。
4. **继续旧版本。** 旧构件永久保留（决定 16），读者可以留在旧版本：宿主需要的信息（存档
   绑定的构件摘要）与运行时如何打开旧清单；第一阶段只有一个运行时（决定 17），它必须读第一
   阶段所有版本写出的构件与存档。
5. **读者的选择。** 自动迁移、有损迁移需确认、只能继续旧版本或重新开始时，运行时给宿主界面
   的结果形状。
6. **发布前 dry-run。** 作者发布前对现有存档做 dry-run 的接口：输入（新旧构件、存档或其摘要）、
   按类别计数的报告；在哪里运行（发布服务在 Node/Bun 中经 Wasm，对服务器上的存档库，见并行的
   服务器存档同步 ADR 0021），规模上限与抽样。
7. **实现计划。** 实现任务的路径、依赖、检查与冻结语料（迁移前后的存档、恢复声明、分歧
   样例）；需要的能力请求变化（manager 合入）。

并行的 ADR 0022 定义创作与发布接口（草稿记录、发布产物），本 ADR 只定义发布接口中供迁移
与 dry-run 挂接的输入输出。

## 约束

- 满足以上各项的最小设计；复用 ADR 0020 的协调器与现有墓碑，不另起迁移框架。
- 不设计可下载或任意的迁移代码（程序版本文档已排除）；作者能声明的只有数据。
- 只依据代码中实际存在的接口写；引用函数与类型时核对它们存在。
- ADR 控制在约 300 行以内，风格照 ADR 0020：决定与理由，不写教程。
