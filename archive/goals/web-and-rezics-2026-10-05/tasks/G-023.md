## 结果

建立宿主安装的那个 npm 包，并让参考阅读器改为使用它。阅读器外壳、渲染插槽、创作与发布、
服务器同步是后续任务，本任务只做它们要放进去的包。

1. **包。** `packages/narrata/web`，包名 `@rezics/narrata`，版本与 Cargo workspace 相同
   （`0.1.0-alpha.1`），ESM，`exports` 只列需要的入口：运行时 API 与 IndexedDB 存档宿主。
   `bindings/typescript` 是旧 Stage 1–5 栈的绑定，现在占用这个名字：改名为
   `@rezics/narrata-protocol` 并设为 `private`。
2. **构建。** 把 `examples/gamebook-web/scripts/prepare.mjs` 中构建 `narrata-nodes-wasm` 与
   运行 wasm-bindgen 的部分移到包的构建中（`task web:build`），包产出 `dist/`：JS、类型声明与
   单独的 `.wasm` 文件。Wasm 以 `new URL(..., import.meta.url)` 定位，Vite 宿主（REZICS 用 Vite）
   与 Node/Bun 都能加载；也接受宿主传入 URL 或字节。`packages/narrata/kernel/js` 的 IndexedDB
   宿主并入包的产物（移动源码或在构建时打包，选改动小的一种），tarball 必须自包含。优先用仓库
   已有的工具（Vite 8、TypeScript）；需要 wasm-opt 等新工具时记入工具链。
3. **类型化运行时 API。** 在 `NodeBook` 之上包一层类型化的 API：`BookView` 等类型由
   `book-view.schema.json` 生成到包里（不再只生成到示例中）；只用清单打开，宿主提供
   `fetchChunk(id)`，缺块时自动取块重试（`takeChunkRequest`/`loadChunk`）；IndexedDB 存档接线照
   `examples/gamebook-web/src/worker.ts` 现有做法。API 要小，只覆盖参考阅读器今天用到的能力。
4. **参考阅读器改用包。** `examples/gamebook-web` 通过包的公开入口使用运行时与存档宿主，不再
   相对路径引入 `packages/narrata/kernel/js/src` 或 `src/generated/wasm`；`task check:r1` 与现有
   浏览器回归保持通过。
5. **tarball 与安装测试。** `task web:pack` 产出 `npm pack` tarball 并打印 sha256 与 sha512。
   测试从 tarball 安装到仓库之外的临时项目（不用 workspace 链接）：浏览器中只用清单打开示例作品、
   做一次选择、存档后重开；Node 中加载 Wasm 并打开同一作品。
6. **预算。** 记录当前 Wasm 与 JS 的原始大小和 gzip 大小，以测试固定预算（当前值加少量余量）；
   首屏只请求清单与首块（`runtime.spec.ts` 已有类似断言，迁到包的测试或保留并引用包）。
7. 新的 `task check:web`（类型检查、单元测试、tarball 安装测试、预算）记入
   [工具链](../../../../docs/development/toolchain.md)；需要加入 CI 的步骤写进交接（`.github/workflows`
   由并行任务修复中，不要改）。

## 约束

- 最小实现：不做阅读器外壳与渲染插槽、不做创作与发布接口、不做服务器同步、不加框架依赖
  （包本身不依赖 React）。不改 Rust 的公开 API，除非包装时发现缺口（在交接中说明）。
- 不改 `fixtures/compat/` 与任何线格式。
- 端口 4173 与 4183 已被现有回归使用；新的浏览器测试用另一个固定端口并写进工具链。
