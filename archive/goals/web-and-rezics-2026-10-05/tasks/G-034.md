## 结果

交付当前 Goal M1 的公共创作入口与 reader/authoring 构建分离。复用已合入 Rust 创作与发布核心，
不新建编译器、文件适配层、格式或发布框架。先读 ADR 0022、已有 authoring Rust API、Web
build/install/budget 脚本与本 Goal 最新规划；静态审查已经确认发布核心可作绑定基础。

1. `@rezics/narrata/authoring` 与 Node/Bun 可用的 `@rezics/narrata/server`：记录检查/规范化、
   拆分/组装及索引、保留既有 ID 的补齐与新 ID 铸造、可定位诊断、预览对象编译、正式发布与受检
   再读取。使用 Rust `validate_record`、`split_source`、`assemble_records`、`mint_ids`、
   `compose_objects_with_registry`、`publish_records`、`read_publication` 等已实现能力。
   浏览器缺省时钟与随机来自宿主安全能力；允许测试注入；不得用 Math.random 或替宿主生成数据库 ID。
2. Wasm 使用独立的 `narrata-authoring-wasm` crate；TypeScript 类型由权威 Rust schema 生成并检查漂移。
   错误保留节点/选择点/输入位置。逐条记录输入、逐个二进制对象输入/输出；发布句柄有显式释放。
   前一发布可以由受检描述与单个对象恢复，不能只接受有 64 MiB 限制的 pack。保持 compiled 与
   switchable、更新与 locked、正文修订与逻辑构件身份的现有区别。
3. reader 默认不含发布/布局/trace 工具。最小兼容拆分：nodes-wasm 的 node-tools 依赖改可选，
   现有 publishGraph 及其 DTO 受默认开启的 legacy-publish feature 控制；旧 dist/wasm 路径保留
   默认构建，另用 --no-default-features 生成 reader-wasm。现有 root runtime 和新的 ./reader
   使用精简构建；保留 LocalContent、migrateR1、pack 接口及旧 raw Wasm 的 publishGraph。
   不复制 RuntimeBook，不新增运行时工厂。reader、兼容、authoring 分别 cargo build，避免将
   authoring 的 feature 合并进 reader。

   `validate_records_with_budget` 目前是 pub(crate)，`validate_project` 仍返回 packed Compilation；
   在共享 authoring 核心补一个很小的 collecting object-compose 入口，复用诊断定位与
   compose_objects_with_registry。不要先调用 packed 校验再编译一次。ProjectSource 不是 serde
   交换类型；源稿便利入口分别接收 ProjectManifest 与逐个 (alias, PackageSource)，主入口逐条接收记录。
4. 独立 tarball 安装测试在浏览器 Worker、Node 与 Bun 使用正式入口，从公开类型构造/修改短篇、
   预览、发布 A，再发布 B；打开输出清单并按需读取对象，旧旅程仍绑定 A。含局部回应、选择、
   延迟后果、参数化子图的现有示例可复用，另用最小三段正文、两选择点、两结局短篇证明公共创作。
   不从安装目录外导入 Rust/源码路径，不调用仓库 CLI 冒充公共 API。补坏记录定位、墓碑/lock 连续性、
   单对象读取、CLI 字节一致、旧 publishGraph 一致、缺省与自定义 Wasm URL/bytes 测试。
5. 各自记录 JS/Wasm 原始及 gzip 预算与首屏请求；首屏不取 authoring、兼容 Wasm、Sigma 或图瓦片。
   保留图预算与已有包安装覆盖。把新 crate 的 tests/clippy/wasm-target 纳入共享 check:r1；CI
   已改为调用该 Task，不重新复制一套 gate。README 仅保留宿主怎样调用/管理生命周期，工具链记录
   实际构建与检查。不要放宽预算掩盖 reader 未拆分。

本任务不做在线存档生命周期、富文档实现、读者地图、演化规划或完整作者编辑器。原生内容适配与
StorageHost 的 pending 写入修复由 manager 并行处理；不要覆盖它们。需要它们的导出时只修改已认领
的组合入口；与 manager 明确核对后接线。不得改变任何已有冻结语料或现有交换格式。
