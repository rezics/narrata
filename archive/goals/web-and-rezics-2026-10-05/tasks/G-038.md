## 结果

完成 Goal M2 存档维护公共接口：受检导入/导出、可继续阅读的浅历史、根/保留策略、完整性扫描、
GC 与配额处理。G-037 关闭后才修改共享绑定、server、生成类型与构建路径。先读 ADR 0015/0017/
0019/0021/0023、History::export/import/export_shallow、collect/integrity_scan、scan_refs/scan_pins、
RefMutation 及现有 Session::page。沿用已交付在线会话与 PostgreSQL 宿主，不另造存档格式或 GC。

1. 公共包提供有界维护操作与结果，通过 Node/Wasm 调同一 kernel；接受受检对象/现有 bundle bytes、
   精确 artifact/execution/cursor 和宿主授权的库，显式释放句柄。保留旧 SessionExport 读取和公共
   export/restore 行为，不能只导出底层 Rust 名字而没有冷启动 CacheStore 的可调用路径。坏摘要、
   未注册 kind、缺对象、超限与冲突有可区分结果；导入验证失败不移动原持久根，不宣布保存成功。
2. 浅历史包装复用既有 bundle 与截断证据。State 没有呈现/旧参数快照，N=0 不能普遍恢复原页面；
   page() 还会跨局部选择回溯 entered 边界。导出时计算并保留重建当前精确页面所需的受检祖先，
   或在导入/恢复前以 history_truncated 拒绝不足上下文；不以 migration_page 代替精确浅恢复。
   在移动 durable roots 前证明当前 page、interaction、变量、调用参数与后续选择一致。跨迁移须
   保留必要构件/描述符/证据；旧祖先真被截断时，完整 export/全程 replay 仍拒绝，不伪造完整历史。
   保留策略是宿主操作参数，无需新 wire format；不重写过去提交、不补造 State 字段。
3. 暴露分页、有界的 refs/pins 与保留根检查，区分活动 cursor、分支、命名存档、固定根及到期 pin。
   删除明确选中的根使用已观察 revision 的 RefMutation CAS，冲突重读，不通过原始对象删除实现
   “删存档”。当前会话、其他 execution、分支、checkpoint、pin、effect 与迁移证据仍由已有闭包保留。
   操作绑定不可变 store ID/账号代次；关闭、删除/重建库与迟到维护回包不能复活旧库。
4. collect/integrity_scan 走现有注册器与 graph/sweep 栅栏。维护入口要求可信时钟、明确 grace、
   dry-run 与有限对象/字节/页/工作量预算；不得直接采用 RetentionPolicy 的 now=u64::MAX 默认值。
   限额不能把局部扫描当完整 mark 后删除，未知 kind/坏引用须拒绝破坏性工作。dry-run 不写入，报告
   候选/保留/回收量与限制；冲突或缓存缺页按既有加载/重试机制处理，不绕开原子 flush/持久确认。
5. 复用 PostgresStore 的现行配额与原子回滚，公共维护包装提供授权库的用量/配额结果及显式清理
   后重试旅程；quota 拒绝不覆盖原进度，GC 不承诺一定腾出空间。服务器通过现有 CacheStore /
   TransactionalSql 边界运行同一受检维护过程，不另写解释叙事的 SQL，不自动迁移宿主表。ADR 0021
   推迟的在线库原地浅压缩、shadow 库构建/CAS 切换、布局迁移与后台调度不在本任务实施。
6. 独立 tarball 在浏览器、Node/Bun 从公共入口完成导出→冷库导入→重开→继续选择、浅导出/恢复、
   根 CAS 删除→dry-run→GC、配额失败→安全清理/重试。CacheStore 与真实 PostgresStore 都走冷缓存，
   不能只测 MemoryBackend 或已热 Session。覆盖局部回应/多选/延迟后果/参数化调用/结局、N=0 与
   页面边界最小保留、截断拒绝、proposal 与多次迁移、旧格式、损坏/超限、多个根/pin/effect、
   未知 kind、并发写/删根/GC、过期策略与关闭/账号切换；导入及维护失败后旧持久旅程仍可重开。

GC、完整性扫描等后台维护能力放在按需 authoring/server 模块，复用现有独立 Wasm；reader 只保留恢复/阅读确需的薄接缝，不因新增维护出口而把整套后台工具带进首屏，也不另起维护框架。
narrata-authoring-wasm 的直接依赖与公共类型可在认领内最小扩充。
nodes-wasm 只补必要的浅恢复/会话接缝。loadMaintenance 等命名由实际公共 API 模式决定，不要求新包或新编译器。

已有 v1 传输具备 key/digest 范围、缺失点读、对象/键删除及 store ID/revision CAS，不因尚无包装
而新增维护 opcode。注意 CacheBackend 的 `limit + 1` lookahead：1024 默认扫描不能发出 1025
项请求，须连同内部 scan_every 正确限额。StorageHost 合并全部未确认 batch 后仍受 10000 ops /
64 MiB 总 flush 约束；不能只限制单个 batch，也不能把原子操作拆成部分成功。collect/integrity
需要累计预算，在超限分配/变更前拒绝。配置配额不是 v1 元数据；可用宿主已授权 accessor，不
向原 v1 偷加字段。只读 CacheBackend 可在无 pending 时采用新 StoreState，维护句柄仍须在异步
边界检查预期 store ID 与账号代次。详细源码审查在 manager 的 `.temp/maintenance-seams.md`。

类型、schema、边界检查和行为测试表达契约；收缩 storage-and-saves 到宿主策略与操作理由，README
只保留最小公共调用/生命周期示例。不修改任何 frozen fixtures/compat 或 REZICS；确需改变存储/
交换格式时先向 manager 提交具体 ADR 与旧读/迁移需求，不私自扩展现有版本。
