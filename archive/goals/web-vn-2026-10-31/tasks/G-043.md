## Runtime and media boundaries

- Add a VN-only presenter/controller and a narrow first-party player capability (separate
  optional entry if useful). Reuse the accepted public VN reader, Session/cache/storage and
  existing content resolver patterns. Do not widen Gamebook reader/controller/BookView or
  duplicate its entire online/evolution/maintenance framework.
- Expose checked, discriminated image/audio resolver request/result types. Bind requests
  to exact immutable MediaRef, artifact, execution/current Commit and captured host context;
  validate role/category, revision, selected variant and descriptor fields. Keep this first
  callback in-process; no new JSON network protocol or persistent variant/scene fields.
  Host owns resolved bytes, locale, authorization and resource addresses. URL, credentials,
  DOM/media handles, decode buffers and playback heads never enter narrative saves.
- Confirm logical input through the reader before preparing presentation. Initial required
  text/visual resources pending show loading/unavailable; after progression retain the last
  complete screen behind the noninteractive veil until the new full target is ready. Retry
  resources only, with no second Advance/Choose. Distinguish pre-commit logical chunk failure
  (retry the original expected input), unknown storage outcome (retry original save bytes or
  reload durable progress), and post-commit media failure. Never turn a failure into ending.
- Full scene targets replace background and ordered stable character layers. Clear omitted
  layers. Reopen/checkout reconcile the current target without historical animation/effects.
  Render speaker only from a current dialogue interaction; render choice prompt/labels from
  current typed references, without hidden story conventions or invented runtime globals.
- Capture generation/context for every async operation; cancel with AbortSignal and discard/
  release late results. On account/library/authorization/content-context change, clear old
  private presentation and resources immediately; retaining the old screen is only valid
  within the same context. Close/switch stops audio, revokes URLs and releases owned leases.
  Media cache cleanup must leave narrative saves and unconfirmed writes intact.
- Bound current resource requests, concurrency, encoded bytes and retained decoded resources;
  report exhaustion as a resource state rather than silently dropping required images. This
  first player need not implement all candidate prefetch/lookahead: VN2 remains required.
  Use exact versions, no latest/same-key fallback. Immutable byte reuse requires matching
  variant plus host authorization/content scope; artifact alone is not a privacy cache key.

## Audio and reference story

Apply a forward music action once per entering Commit. Restore/checkout align full targets
and restart music/current-line voice from zero; old voice is stopped and never replayed.

autoplay rejection, decode failure and interrupted loads with retry or muted continuation.

Use real decodable music and short spoken voice clips, not silent/beep placeholders for
speech. Local offline Windows speech generation is acceptable for host fixtures; never call
a paid service or require credentials. Record any new generation tool/procedure in toolchain.
Assets/body/audio belong to the simulated host/product, not the SDK's narrative objects.

two distinct backgrounds and visible layer changes, music and at least one current-line
voice. Reuse native compile helpers as needed until public authoring is delivered; do not
implement that authoring subsystem here. Serve immutable manifest/chunks/assets with exact
IDs/versions; first screen must not download the whole story or second scene's resources.
