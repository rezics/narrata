# 图、分析与摘要

状态：目标契约，尚未实现。依据：[决定 7、12](../product/decisions.md) 与
[图渲染调研](../research/2026-10-05-choice-granularity-and-scale/graph_rendering.md)。

叙事图归 Narrata，与宿主的章节结构无关。图视图是用户需求，但它是程序的一个投影，
不是另一份真相。

## 发布时计算

由 Rust 工具链在编译或发布时完成，同一实现可在 CLI、服务器任务和浏览器 Worker 中运行：

1. **拓扑分析**：合并平行边、标记环与回边、从入口的可达性、不可达节点、死路、结局集合、
   支配节点与瓶颈段。作为诊断输出给作者，也作为每个节点的分析列。
2. **层级**：先用作者组织（作品 → 内容单元 → 单元内），单元过大（约 2–5 千节点）时在瓶颈
   或环处再切分。
3. **布局**：每个簇内做分层布局，再排列簇。为每个节点保存稳定的排序键和坐标，编辑一个簇
   不移动其他簇。浏览器中的分层布局库在 1k–10k 节点就已不可用（dagre 1k 节点 52 秒，elkjs
   10k 节点 400 秒未完成），因此不在浏览器做整图布局。
4. **细节层级**：作品级（簇与聚合边）、簇级、节点级瓦片（每块约 500–2,000 个元素），并带
   重要度，决定各缩放级别显示哪些标签。
5. **交付格式**：按簇或瓦片的列式二进制块（类型化数组），内容哈希命名。合成的 30 万节点、
   90 万边约 2.3 MB brotli；把每个节点建成 JS 对象才是内存瓶颈（约 390 MB 对 11 MB）。

## 作者视图

- WebGL 渲染器（sigma.js + graphology，懒加载）；同时绘制不超过约 5 万节点、15 万边。
- 通过"进入单元"切换层级；局部编辑用小的富节点编辑器（不超过约 500 节点）。
- 全作品星图可选，用 GPU 渲染器（cosmos.gl）加预计算坐标。

## 读者地图

- 由服务端按读者走过的节点和边生成；可选显示"见过但未选"的选项占位。**不下发未揭示的
  节点**，下发即剧透。
- 位置取自全局布局并压缩空隙，避免泄露隐藏分支的规模；新揭示的节点插入而不重排。
- 形式参照分章流程图（Detroit: Become Human、Zero Escape）：章节概览 + 单章流程图，作者
  定义的锁，跳转即恢复读者自己在该节点的存档。
- 社区选择比例只在达到聚合阈值后显示。

## 语义摘要

供宿主写入自己的索引或图库（REZICS 的 Jena）的中立摘要，每次发布导出一次：

- 作品是互动叙事；当前发布的构件摘要；
- 入口、结局及其分类；
- 路线与参与路线的内容单元；
- 人物或实体在哪条路线、哪个节点首次出现（用于宿主的剧透边界）。

摘要不含选择边全集，规模为每部作品几十到几百条事实。格式为带版本的 JSON，宿主负责映射到
自己的词汇。
