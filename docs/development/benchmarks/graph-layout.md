# 发布时图分析与布局基准

2026-10-05，在 Windows x64、Intel Core i9-14900HX（24 核 / 32 线程）、约 32 GiB 内存上运行。
Rust 1.98.0，单线程 release 构建；没有图算法依赖，没有 GPU 或浏览器布局。

## 复现

从仓库根目录运行，经 Goal 的重型槽位独占基准：

```powershell
task goal -- slot --heavy -- pwsh -NoProfile -File packages/narrata/tooling/crates/narrata-graph/benchmark.ps1
```

[脚本](../../../packages/narrata/tooling/crates/narrata-graph/benchmark.ps1) 构建并启动
[原生 runner](../../../packages/narrata/tooling/crates/narrata-graph/examples/graph_layout.rs)，
每个规模独立启动三次。结果 JSON 与压缩测量用的列缓冲放在 `.temp/graph-layout/<随机目录>/`。
runner 的 `--nodes` 可用于其他规模（500 的倍数，上限见检查后的输入类型）。

合成图每个作者簇 500 个节点、20 个选择点，选择在三步内局部汇合；每簇一个短环，每十簇
一个跳过相邻簇的分支，最后两个节点是不同分类的结局。它检验常见的局部汇合结构，不代表
稠密图、任意长边或大量结局的最坏情况。

## 测量

耗时为三次运行的中位数。`prepare` 包含受检输入、平行边合并、全部拓扑诊断、层级、布局、
三层列式瓦片与内存语义摘要；列打包是额外的整数小端转换，不含文件写入与 gzip。

| 节点 / 原始边 | 作者簇 / 瓦片 | prepare | prepare + 列打包 | 峰值工作集（最大） | 列总字节 | 每瓦片 gzip 列字节 |
| --- | --- | --- | --- | --- | --- | --- |
| 10,000 / 10,421 | 20 / 41 | 11.75 ms | 12.09 ms | 11.51 MiB | 756,325 | 93,289 |
| 100,000 / 104,219 | 200 / 401 | 132.75 ms | 136.09 ms | 60.87 MiB | 7,564,195 | 933,473 |

10 万节点明显低于“数十秒”的计算目标。这里只证明 Rust 内存计算与列打包；尚不包含
规范 CBOR 写入、内容寻址、受检瓦片解码和版本 JSON 摘要，不能把表中的字节数当作已冻结
的发布格式大小。

Windows 脚本每 10 ms 读取子进程的 `PeakWorkingSet64` 历史峰值，runner 在输出后保留
200 ms 供采样。工作集包含生成器、输入、输出、分配器和打包缓冲，不是 Rust 分配字节数，
也不是 Wasm 或浏览器内存。gzip 对每个列缓冲独立使用 .NET `SmallestSize`，不跨瓦片共享
字典。规范外层的粗略预算另记每瓦片 256 字节（包括 kernel 56 字节信封及列 byte string
头和元数据）；10k 为 10,496 字节、100k 为 102,656 字节，实际数字须在格式落地后重测。

## 取舍与尚待验证

最长路径分层与两轮整数重心排序足以处理局部汇合，成本与结果易于复现；不引入 network
simplex 的优化与调参。支配树用 [Lengauer–Tarjan 的简单算法](https://doi.org/10.1145/357062.357071)
并将遍历和路径压缩改为迭代，以避免长链的递归深度和支配集合的平方级内存。

作者簇的框架按固定容量留位，内部几何只依赖该簇，簇之间只依赖去重后的簇关系。这使内部
编辑不移动其他簇，但全局坐标会留出很大的空白：作品概览使用紧凑坐标，进入簇后使用局部
坐标。跨簇关系变化可以移动簇；尚未实现持久布局快照或跨关系编辑的增量稳定性。

超过 4,096 节点的簇在预算附近优先沿瓶颈或环切分；无此结构时按预算切分，巨大环也必须
切开。节点级瓦片同时限制节点和边总数为 2,000，端点通过带簇索引的 ghost 行补齐，高度数
节点可以跨多块。排序、坐标、诊断和列缓冲的确定性由测试覆盖；受检二进制往返尚待格式任务。

语义摘要按结局反向遍历，成本为 `O(结局数 × (节点 + 边))`，这是大量结局时的明确瓶颈。
公共瓶颈序列按连续作者簇压缩为首节点、末节点与计数；基准分别得到 18 与 180 段。
任意图的摘要不能保证固定条数（例如反复跨簇的长瓶颈链），实现不静默截断事实。

目前没有输出格式 ADR 与冻结语料的认领。发布用 CBOR 字段、kind code、object id 命名、
受检读取和版本 JSON 摘要必须由后续任务一起固定；测量用 `.columns` 文件没有读取协议，
不能分发给宿主。实体首次出现仍等待实体模型，真实作品的交叉质量也尚未验证。
