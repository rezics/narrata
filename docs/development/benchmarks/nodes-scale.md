# 合成作品与按块加载基准

2026-10-05，Windows x64，Intel Core i9-14900HX（24 核 / 32 线程），31.7 GiB 内存，
Rust 1.98.0，原生单线程 release 构建。这里测程序结构与运行时，不解析正文，不包含网络、
Wasm、浏览器渲染或宿主内容缓存。

## 复现

```powershell
task goal -- slot --heavy -- task bench:nodes
```

[脚本](../../../scripts/benchmark-nodes.ps1) 为每个规模生成一次构件，再为缓存容量
1、16、64 分别启动三个独立读者进程。`task bench:nodes -- -Repetitions 1` 可用于快速复现，
worker 仍通过重型槽位运行。真实 pack、独立清单、墓碑、块信封、生成阶段测量和读者结果
放在 `.temp/nodes-scale/<随机目录>/`。这些独立对象与 pack 内对象逐字节相同，沿用
[ADR 0013](../../adr/0013-r2-text-free-node-format.md)，没有增加线格式。

[生成器](../../../packages/narrata/tooling/crates/narrata-node-bench/src/lib.rs) 经公开的
`compile` API 编译。种子为 `0x4e41525241544101`；身份、选择顺序和源稿全部确定。
每内容单元 20 个选择点，每章五个单元，95% 的选择点全部是带回应引用与汇合锚点的局部结果，
5% 的选择点进入另一段落；平均每点 2.4 个选项。21 个包中的章节经 `call` / `return`

章节调度图。选项标签也是引用；没有生成或嵌入正文。数据形状取自

## 测量边界

[原生 runner](../../../packages/narrata/tooling/crates/narrata-node-bench/src/main.rs) 的生成进程
与读者进程分开。读者的 `ChunkSource` 按对象摘要从文件读取，不持有全 pack；
`MemorySource` / `Program::from_pack` 会保留全部编码字节，不能用来证明分块读者的内存结果。

打开阶段包含读取与受检解码清单、墓碑，不读取任何块。首屏阶段包含初始化 Session、运行到
第一个选择、创建根提交与固定当前帧。首屏传输字节是打开字节加首块信封，不包括可选名字表。

计数分配器统计 Rust 请求的字节：`allocated_bytes` 是累计申请量（realloc 按新请求大小计入），
`live_bytes` 是阶段结束时仍存活的量，`peak_live_bytes` 是阶段内存活请求量的峰值。
`retained_extra_bytes` 与 `peak_extra_bytes` 相对阶段起点，净释放时前者为零。
这些量不包含分配器元数据、堆碎片、栈与代码页。分配器的 unsafe 仅用于把原始参数原样转交
`System`，不解引用指针；生成器和节点库禁止 unsafe。

选择耗时包含 `Session::choose` 的校验、执行、提交、状态摘要以及新旧帧 pin 的转交；
不包含宿主提前找出要选的选项。缓存未命中时包含文件读取和再次受检解码。
预分配的耗时采样数组不计入游玩阶段新增申请量。之后释放 Session 与帧 pin，另作全作品
扫描以观察缓存驻留；扫描不算游玩，不产生提交。脚本检查重复运行的分配字节与摘要相同，
并检查不同缓存容量得到同一最终提交和状态。

Windows 父进程每 10 ms 读取读者的 `PeakWorkingSet64`；读者输出后保留 200 ms 供采样。
该历史峰值含整个读者进程、堆碎片与全扫描，只作参考，不包含另一个生成进程。
时间取三次中位数，max 与 Windows 工作集取三次最大值；确定性字节数只列一次。

## 打开与首屏

首屏新增块的信封是 7,339 字节；各规模、各缓存容量都只读一个块，打开阶段读零个块。
这组历史测量还读取了 63 字节墓碑信封；现在的清单打开 API 允许普通首屏省略它，
墓碑在 lookup、提议与完整校验时才加载。

| 选择点 | 打开传输字节 | 首屏累计传输字节 | 打开申请 / 保留字节 | 首屏新增申请 / 保留字节 |
| --- | --- | --- | --- | --- |
| 10,000 | 9,320 | 16,659 | 141,988 / 53,821 | 113,639 / 57,279 |
| 100,000 | 66,787 | 74,126 | 1,053,283 / 349,762 | 113,644 / 57,279 |

首块的结构不随总规模增长；清单中每图的签名、块位置与摘要需要常驻，所以打开内存仍随
图数增长。这里证明的是避免常驻全部图体，不是清单的常数内存。

默认容量 16 时，最终实现的打开与首屏阶段中位耗时分别为 0.747 / 0.595 ms
（10,000 点）和 3.264 / 0.685 ms（100,000 点）。首屏新增申请量基本不变。

## 游玩与全扫描

本组历史测量的游玩原计划是 10,000 次选择，当时参考 `Session` 保留至多 512 个提交（含根），
各次运行都在第 512 次选择时报 `history_limit`，实际样本为 511 次，涉及 8–9 个块。
因此以下结果只证明短程选择分布，不能验收“一次游玩数千次选择、跨越大量图”。
不能把多次重启 Session 的样本合并，声称完成了同一次长程游玩。

| 选择点 | 缓存容量 | choose p50 | choose p99 | choose max（三次最大） | 游玩最大驻留块 |
| --- | --- | --- | --- | --- | --- |
| 10,000 | 1 | 10.6 µs | 1,151.4 µs | 1,468.0 µs | 3 |
| 10,000 | 16 | 11.0 µs | 1,051.5 µs | 1,381.9 µs | 9 |
| 10,000 | 64 | 10.9 µs | 1,068.2 µs | 1,366.5 µs | 9 |
| 100,000 | 1 | 11.1 µs | 1,155.9 µs | 1,967.7 µs | 3 |
| 100,000 | 16 | 11.0 µs | 1,108.7 µs | 1,309.3 µs | 8 |
| 100,000 | 64 | 10.9 µs | 1,103.7 µs | 1,321.7 µs | 8 |

恢复运行后的结果没有达到“每次选择低于 1 ms”：默认容量在 100,000 点时的最大值是
1.309 ms。首次完整运行的同规模、同容量 p50 / p99 / max 为 4.4 / 444.3 / 546.1 µs；
构件、状态与提交相同，时间不相同。不能把较快的一轮当成稳定保证，
也没有覆盖第 512 次之后的长程历史成本。单独的 `Session::view`、`page` 与完整历史
呈现不在该 choose 分布里。

同步读块与受检解码是长尾的候选瓶颈：511 次选择只有 7–10 次额外读块，多数选择很快，
较慢的约 1% 足以使 p99 过线。这是根据分布与读块计数的推断，尚未分别剖析文件读取、
受检解码、重编码检查、结构校验和分配的耗时，也未解释恢复前后的机器时间差异。

| 选择点 | 全扫描最大驻留块 | 测量阶段最大存活申请 / 扫描后存活字节 | Windows 全读者峰值工作集（三次最大） |
| --- | --- | --- | --- |
| 10,000 | 1 | 1,365,809 / 117,357 | 6,467,584 |
| 10,000 | 16 | 2,401,113 / 1,944,588 | 9,089,024 |
| 10,000 | 64 | 8,479,441 / 8,022,916 | 18,149,376 |
| 100,000 | 1 | 1,689,867 / 413,284 | 7,139,328 |
| 100,000 | 16 | 2,994,800 / 2,575,352 | 10,248,192 |
| 100,000 | 64 | 10,146,549 / 9,727,101 | 21,364,736 |

存活申请峰值取打开、首屏、游玩和全扫描四个计数阶段的最大值；包含阶段起点已存活的
申请与固定的测量数据，不包含结果 JSON 输出阶段。容量 1 时的峰值来自保留 512 个提交
的游玩阶段，容量 16 / 64 时来自全扫描。

完整扫描覆盖 121 / 1,021 个图。固定容量下总量扩大十倍没有扩大十倍的常驻图体；
容量从 16 到 64 时保留的图体则明显增加。剩余差异来自清单大小、保留的最后若干图的
不同大小、分配器和页驻留。100,000 点、容量 16 的 511 次游玩累计申请 4,391,247 字节，
全扫描累计申请 328,751,708 字节；累计申请的大数字并不意味着同时保留这些字节。

这组表来自最终实现的完整三次运行记录 `.temp/nodes-scale/26f366b345304dcc9f1e5f832cb8f345/results.json`。
恢复后的第一次记录是 `.temp/nodes-scale/0597aaf08b7e41058a76647c0f521dd4/results.json`。
首次完整记录是 `.temp/nodes-scale/5ea3e8abd255406c9dc59dcbb7ae0138/results.json`。
首次运行与恢复后第一次运行的分配计数相同；最终实现使 pin guard 拥有共享缓存句柄，
打开的累计与保留申请增加 24 字节，其余阶段的新增申请量不变。guard 可以由 Session 持有，
也可以独立于 Program 存活；没有自引用生命周期要求。
100,000 点的构件 ID 是
`artifact:0ed0bc62f856358a11dfaabc8a7159f0ef573fe2096f26750e52c00b51f0cbcb`。
各容量的最终提交与状态摘要一致；同规模、同容量三次的分配计数一致。

缓存默认容量为 16。当前态的帧通过 `Program::pin_state` 的独立 guard 保留；
转交时先固定新态，再释放旧 guard。容量 1 时当前调用栈可使驻留数达到 3，
调用栈优先于预算；全扫描释放了帧 pin，因此驻留不得超过配置容量。

节点库的测试覆盖 64 层调用栈在容量 1 下全部保留、多个 guard 独立释放、guard 拥有的缓存生命周期、
失败 pin 回滚、真正的 LRU 次序、借出的 `Arc<Graph>` 仍有效、淘汰后重新校验损坏字节与
错误对象摘要，以及不同容量下的状态、提交、呈现、重放和恢复一致。

## kernel 历史层的长程游玩与预取

接入后的正式记录为 `.temp/nodes-scale/5d6fa6541fa6498a8cc1cc7f648b9ae3/results.json`。
两个规模、三个缓存容量各跑三次；每个进程在一个会话中完成 10,000 次选择，再导出并受检恢复
当前 checkpoint，比较游标与完整 State。18 次共 180,000 次选择，全部完成，没有拼接重启样本。
跨容量的构件、最终提交与状态摘要一致，重复运行的分配计数一致。

宿主在交互间调用 `Session::prefetch`，沿候选路径准备受检图，遇到交互停止，并考虑当前调用栈
返回后的续点。每条路径最多探查 64 步，总探查数最多 4,096；借出的图在选择前保留，选择成功、
checkout、恢复与加载存档后释放。阅读器在发布 view 前准备下一次选择；失败的预取不改变提交，
选择仍走正常受检加载。表中的 choose 不包含单独计时的预取、view、page 或 IndexedDB 确认。

未固定块的驻留数仍不超过容量 1 / 16 / 64。

正式记录的全部 180,000 次选择均低于 1 ms，最大值为 572.0 µs。前一轮包含
checkpoint 的记录 `461aa1a35e5347ccba5caa7d19eb7089` 曾出现 1,848.2 µs 的暖选择；

数据集的存储后端为 MemoryBackend，

“单次选择低于 1 ms”的测量前提是宿主在交互之间完成下一批可能进入的块的预取，
包括候选调用与当前调用栈返回后的续点。它不是未完成预取时的冷选择保证：同步加载与
受检解码需要单独计入冷启动或预取预算，不能藏入暖选择分布。

| 阶段（100,000 点，容量 16） | 同步加载与受检解码边界 | 已测耗时 |
| --- | --- | --- |
| 冷启动：打开 | 历史 runner 读取并解码清单与墓碑，不读程序块 | 3.264 ms（打开中位数） |
| 冷启动：首屏 | 首块同步读取、受检解码、初始化会话与根提交 | 0.685 ms（首屏中位数） |
| 交互间预取 | 同步读入并准备候选块，不计入 choose | p99 1.0239 ms；max 6.3295 ms |
| 未预取的冷选择 | 加载、受检解码与选择全部同步发生 | 101 次冷选择的 p50 1.3011 ms |

不能把它们当成 Wasm 或网络耗时。清单打开 API 现在也允许墓碑按需获取，普通首屏只需
清单与首块；上述历史测量仍包含 63 字节墓碑，不据此倒扣未重测的耗时和内存。

## 结论与未完成部分

10 万选择点已能经公开编译 API 得到受检 pack；历史基准首屏读取清单、墓碑与首块，
全部 1,021 块扫描后也不会积累为常驻图体。内存组成是清单、活跃或缓存中的图、
会话历史与一次解码的临时申请量；累计申请量随访问次数增长，与峰值常驻量不同。
每图约 30 KiB，当前证据还不足以要求切分单图，不提出新的块格式 ADR；
分组计时已将主要长尾定位于冷块准备；预取后的选择分布与归档成本见正式记录。

会话已自动持有当前态的帧 pin，初始化、选择、提议、checkout 与 restore 在替换 guard 前
先固定新态；失败保留旧 guard，各会话可独立移动与释放。运行时在 call / return 时同步
工作态的 pin，并把最终 guard 交给会话。runner 不再显式固定帧。
[块缓存测试](../../../packages/narrata/nodes/crates/narrata-nodes/tests/chunks.rs) 覆盖容量 1 下
64 层连续自动调用与返回：每个活跃块只加载一次，返回后缓存回到预算；也覆盖恢复、检出、
独立会话与失败选择的 guard 生命周期。旧的 511 次选择表只描述接入前的实现；
接入后的延迟、预取与内存测量使用长程正式记录。

会话现由 kernel 历史层驱动，512 提交限制已移除。节点采用 kernel 的五字段提交编码；
临时三字段根只读，导入重映射提交与游标，State / Input 字节保留。
[历史层测试](../../../packages/narrata/nodes/crates/narrata-nodes/tests/history.rs) 覆盖冻结语料、
存档槽重开、checkpoint 与受检导入；编码修订见 [ADR 0013](../../adr/0013-r2-text-free-node-format.md)。
长程游玩、存档往返与预取测量见上节；默认容量的 100,000 点样本达到 1 ms 目标，其他样本的偶发超时如实保留。
