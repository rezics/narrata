## 结果

浏览器里的 Wasm 运行时（节点阅读器与旧协议引擎都会用）能把 kernel 存档持久化到 IndexedDB：
增量、按需读取、刷新与多标签页安全，而契约保持同步（[ADR 0012](../../../adr/0012-narrow-storage-backend-contract.md)
"同步接口"一节预告的"引擎产出批次、宿主落盘后确认"）。`narrative-core` 将据此把节点阅读器从
"整份会话一条记录"改为 `narrata-history` 之上的存档；`web-and-rezics` 的 npm 包会封装它。

## 要求

- **不整库加载。** 打开存档与推进一步只从 IndexedDB 读取引擎实际需要的键与对象（与
  [ADR 0014](../../../adr/0014-save-engine-key-layout.md) 的计数断言同一标准）。
- **先落盘后发布。** 一个批次在 IndexedDB 事务完成之前，宿主不得发布依赖它的结果（ADR 0011
  的规则）。
- **多标签页。** 另一个标签页先写入时，本标签页的下一次落盘被检测为冲突并整体失效重载，
  不得静默覆盖；修订号全库单调（ADR 0012）。
- **持久性。** 声明为可被驱逐（`Evictable`）；适配器提供 `navigator.storage.persist()` 请求与
  "整库导出/导入"或经 checkpoint bundle 的导出，供 Safari 7 天清理后恢复。
- 默认方案（理由写进 ADR，可以在比较后改）：Rust 侧一个实现 `StorageBackend` 的缓存后端——
  读取未缓存的键、对象或扫描范围时以一个新的、明确"无效果"的错误中止当前操作并报告所需项；
  宿主异步取回后预载并重试该操作（引擎的操作先读后写，中止无副作用；`narrata-history` 需要把
  这个错误原样上抛而不是当作损坏或结果未知）。写入先在缓存上判断前置条件，进入待落盘队列；
  宿主按顺序在一个 IndexedDB 事务里写入并核对全库修订计数，成功则确认，冲突则缓存作废。
  ADR 里简要比较全量预载、OPFS 同步访问句柄（SQLite-Wasm）等替代方案并说明取舍。
- 批次与取数请求跨 Wasm 边界的编码是交换格式：用 ADR 0003 规范 CBOR，写进 ADR 0017。

## 交付

1. ADR 0017。
2. `narrata-storage-host`（或 `narrata-storage` 的一个 feature，选简单的）：缓存后端与协议类型；
   通过 `narrata-storage` 一致性套件（用一个模拟的同步宿主驱动"缺数据→预载→重试"与落盘确认），
   并测试冲突失效、确认前崩溃（重开后状态等于最后确认的批次）。
3. `narrata-history` 对新错误的处理，以及一个测试：计数器领域在缓存后端 + 模拟宿主上创建、
   推进、重开加载，宿主读取的项数不随历史深度增长。
4. `packages/narrata/kernel/js/`：TypeScript 的 IndexedDB 适配器（取数、按批落盘与修订核对、
   导出导入、persist 请求），vitest + fake-indexeddb 单测；以及一个真实浏览器测试（Playwright，
   版本与 `examples/gamebook-web` 一致）：构建一个小的 Wasm 测试模块（计数器领域 + 缓存后端，
   用 wasm-bindgen 暴露），在页面里推进、刷新后继续、两个标签页冲突被检测。不要依赖或修改
   `examples/gamebook-web` 与 `bindings/typescript`（旧的 `indexeddb-store.ts` 留给协议任务）。
5. 新工具或依赖记入 [工具链](../../../development/toolchain.md)；`scripts/check-g2.ps1` 加入新 crate
   的测试与 wasm32 检查。浏览器测试的入口加进 Taskfile 需要的话（`Taskfile.yml` 无人认领，最小改动，
   列入 OWNER CHANGES）。

## 不要做

不改节点栈、阅读器、协议引擎、`bindings/**`；不做 async trait；不改 ADR 0014/0015 的键布局与
对象格式；不做 OPFS 实现（只在 ADR 里比较）。
