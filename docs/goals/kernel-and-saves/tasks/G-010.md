## 结果

Goal 验收"协议引擎不再写死内存存储"。`ProtocolEngine`（`crates/narrata-protocol/src/engine.rs`）
今天在 `Session` 里写死 `MemoryStore`（约第 76、229、329、584、1086 行），并自己重写了一遍创世、
提交、输入复用与目录事件（`commit_draft` 等），没有用 `SessionCoordinator`。改为：

1. 会话存储可注入：引擎按一个后端工厂（或泛型参数 `B: StorageBackend`，选调用点最少改动的
   形式）创建与加载会话的存储；默认仍是内存，现有 FFI/Wasm/绑定行为不变。Rust 宿主可以传入
   SQLite 后端（`narrata-storage-sqlite`）——加一个测试：用 SQLite 后端创建会话、推进、丢弃引擎、
   用同一文件重开并继续。
2. 删除重复的提交路径：引擎的创世、派发、输入复用、checkpoint/timeline 导出导入走
   `SessionCoordinator` 与 `narrata-store` 的公开 API。如果 coordinator 缺少引擎需要的某个入口，
   在 `coordinator.rs` 里做最小补充。
3. 顺手修复：`result_dto` 丢掉了 `speaker`（engine.rs 约 989 行）；补上并加测试。

## 约束

- 协议的线格式（`proto/narrata.proto`、`PROTOCOL_ABI_VERSION`）、生成代码与冻结语料不变；
  `crates/narrata-protocol/tests/conformance.rs`、.NET 与 TypeScript 一致性跑法都不改并且通过。
- 最小改动：不加新的协议消息、不做跨 ABI 的宿主存储回调（浏览器侧由另一个任务的缓存后端与
  批次确认协议解决），不重构 coordinator 的其他部分，不新建抽象层。改动远超上面三点时停下来
  交接说明原因。
- 另一个任务同时在 `packages/narrata/kernel/crates/narrata-storage*`、`narrata-history` 与
  `packages/narrata/kernel/js` 工作，不要碰它们。
