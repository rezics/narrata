## 结果

[决定 2](../../../product/decisions.md#2-内核不含正文) 落到旧 Flow/Statechart 栈：Program 与 Snapshot
不再含读者文本，改一个字不改变 `ProgramArtifactId`、`StateDigest`、Snapshot、回执或提交的任何
字节；`SceneState` 成为可选组件。新格式有 ADR 0018 与新冻结语料 `fixtures/compat/stage6-v0/`，
旧 `stage5-v0` 语料继续可读并能迁移到新格式。

现状（调研见 `docs/research/2026-10-04-engine-core-and-storage/report.md` "改什么"表第 7、8 行）：

- 文本是 `ProgramArtifactV0.constants` 里的 `Value::String`，由 `OpV0::Say { speaker, text }`、
  `OpV0::Choice { prompt }`、`ChoiceArmV0.label` 以 `ConstIndex` 引用（`program/instruction.rs`、
  `program/wire.rs`、`program/validate.rs:374-411`），因此进入 `ProgramArtifactId`。
- 运行时把文本复制进状态：`PendingInteractionV0::Say/Choice`、`PendingChoiceItemV0.label`
  （`runtime/interaction.rs`），由 Snapshot 编码（`snapshot/wire.rs:180-235,520-560`），恢复与迁移
  时对照 Program 常量重建（`snapshot/restore.rs`、`migration.rs`），进入 `state_digest`。
- `RuntimeStateV0.scene: SceneState` 不可选（`runtime/state.rs:24`），线上已在默认值时省略。
- 协议 DTO 带文本（`proto/narrata.proto` 的 `Result.text`、`Choice.label`），`result_dto` 丢掉了
  `speaker`；.NET、TypeScript、Unity 绑定与呈现接口按文本工作。
- 内容引用类型已在 `narrata-kernel` 的 `content` 模块（`ContentRef`、`Segment`，规范 CBOR 与
  受检解码；节点栈 R2 已在用，见 [ADR 0013](../../../adr/0013-r2-text-free-node-format.md) §2）。

## 已定的方向（细节与理由写进 ADR 0018）

- Program v1：一张内容引用表（`ContentRef`/`Segment`），`Say` 的正文是 `Segment`、`speaker`、
  `Choice.prompt`、选项文字是 `ContentRef`，指令按索引引用；`constants` 中的字符串只留给参与规则
  的数据。引用（provider + key）属于结构，进入构件身份；它们解析到的文字不进入。接通
  `ExternalContentDeclV0` 占位类型或删掉它，二选一。
- Snapshot v1 / 运行时状态：待处理交互只记录引用（按索引，恢复时对照 Program 校验），
  `scene: Option<SceneState>`；视图与协议输出内容引用，由宿主解析（[内容引用契约](../../../contracts/content-references.md)）。
  呈现键 `(ExecutionId, CommitId, 出现位置)` 若容易给出就在视图里给出。
- 协议：新的 ABI 版本，`Result`/`Choice` 携带内容引用（并修复 speaker）；旧版本消息的处理写进
  ADR。重新生成 TypeScript 与 .NET 代码，Unity 呈现接口改为接收引用并由宿主解析（保持最小）。
- 迁移：stage5 的 Program v0 + Snapshot v0（以及其上的提交与 bundle）可转换为 v1：每个文本常量
  变为一个本地内容方的引用（provider 与 key 的确定方式写进 ADR，同一输入必得同一引用），并输出
  一个供宿主解析的内容包（JSON 即可）。用 ADR 0009 的迁移机制或一个显式的格式升级函数加 CLI
  入口，选更直接的；`stage5-v0` 语料的升级 dry-run 与升级后继续运行到结束要有测试。
- 新种类的对象 schema 版本在 `narrata-store` 的注册里登记（ADR 0015 的注册表）；ADR 0014/0015
  的键布局不变。

## 交付

1. ADR 0018。
2. 格式、运行时、恢复、迁移、协议与绑定的改动；testkit 生成器产出 v1 程序。
3. `fixtures/compat/stage6-v0/`（与 stage5-v0 同样的一组：program、snapshot、receipt、commit、
   checkpoint bundle、timeline archive，加清单与预期内容）与冻结测试；新增 golden 与负例。
4. 属性测试：只改内容包里的文字时 `ProgramArtifactId`、`StateDigest`、提交 ID 都不变；换
   provider/key 时会变。fuzz 目标覆盖 v1 解码。
5. `docs/architecture/` 中被取代的段落改为指向 ADR 0018。

## 不要做

不改 `fixtures/compat/stage5-v0` 及其他已冻结语料；不改节点栈、`narrata-kernel`（只使用它的
`content` 模块；需要改动时交接提议）、`narrata-history`、`narrata-storage*`、`packages/**`；
不做浅存档；不在 `RuntimeStateV0/V1` 上加新产品能力（决定 11）。
