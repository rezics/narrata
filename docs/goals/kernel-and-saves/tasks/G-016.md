## 结果

[决定 11](../../../product/decisions.md#11-节点组合模型是长期内核的语义基础) 把"Effect 账本、迁移协调"
列为 kernel 能力。今天它们只在旧栈：账本状态机在 `crates/narrata-store/src/engine/effects.rs`（键空间
8、9，ADR 0014），迁移的注册表、路径发现、dry-run 与应用在 `crates/narrata-store/src/migration.rs`，
都绑定旧栈的 ID 类型与 `CommitV1`。[ADR 0015](../../../adr/0015-kernel-history-layer.md) 把它们列为
通用领域的推迟项。本任务把**与领域无关的部分**搬进 `narrata-history`，让任何注册领域（节点栈的
外部效果、生成式内容服务的调用、构件升级）用同一份实现，旧栈改为注册使用者：

1. **Effect 账本。** claim / 租约续期 / 结果记录 / fence / 补偿的状态机与"提交先于派发"的屏障，
   以领域给出的不透明执行 ID 与效果 ID（定长字节）为键；能力名与版本、请求摘要、响应对象是字节或
   对象 ID。旧栈的键空间 8、9 的编码**不变**（`store-layout-v1` 与 `store-sqlite-v2` 迁移结果逐字节
   照旧），通用实现可以用新键空间供新领域使用，也可以证明旧编码已经足够通用而直接复用——在 ADR 里说明。
2. **迁移协调。** 构件注册表、迁移描述的路径发现、dry-run、"迁移提交"的写入（一个批次、一个引用
   CAS）做成通用：通用提交（ADR 0015）的构件变化目前在写入时被拒绝，给它一个显式的迁移输入或迁移
   原因，使领域可以把会话从构件 A 迁到 B（状态的转换由领域给的闭包完成，kernel 只校验链接与原子性）。
   旧栈的 `MigrationDescriptor`/`RelocationTable` 语义与 ADR 0009 的冻结行为不变，改为在通用层之上注册。
3. 用 `narrata_history::testing` 的计数器领域证明两者：效果的 claim/超时/重放复用/未知结果与补偿；
   构件 A→B 的迁移、dry-run、迁移后继续、导出导入。冻结语料 `fixtures/compat/kernel-history-v3/`
   覆盖新出现的对象或键格式（若确实没有新格式，在 ADR 里说明并不建语料）。

## 约束

- 所有现有冻结语料（`stage5-v0`、`stage6-v0`、`store-sqlite-v2`、`store-layout-v1`、
  `kernel-history-v1`、`kernel-history-v2`、`browser-storage-v1`）不变并通过。
- 最小改动：搬移而不是重写；不新增后端、协议消息或 async；不改节点栈（接入由 `narrative-core` 做）；
  不改 `narrata-kernel`、`narrata-storage*`、`packages/narrata/kernel/js`。改动明显超出上面三点时停下来交接。
