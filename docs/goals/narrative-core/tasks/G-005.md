## 结果

按 [ADR 0013](../../../adr/0013-r2-text-free-node-format.md) 把节点栈换成 R2：Narrata 不持有
一个字的正文，示例作品《山口来信》在 Rust CLI 与浏览器阅读器中的阅读体验不变。

交付：

1. **内容引用类型**放在 `narrata-kernel` 的 `content` 模块：`ProviderId`、`ContentKey`、
   `AnchorId`、`ContentRef`、`Segment`，带规范 CBOR 编码和受检解码。kernel-and-saves 的
   manager 已同意你改 `src/content/**`、在 `lib.rs` 加一行 `pub mod content;`，以及在
   `Cargo.toml` 加一个默认关闭的 `serde` feature（serde + schemars）。条件：默认构建只依赖
   sha2/hex/thiserror 且能编译到 wasm32；serde 形式永远不用作身份编码。
2. **`narrata-nodes` R2**：
   - 源稿模型：`id`、别名、`tombstones`、`ref` 标量、`args`、段落/选择点/选项。
   - 编译：包括 ADR 0013 §4 的全部结构规则。
   - 构件编码：清单、程序块、墓碑集、名字表、打包容器，用 kernel 的 CBOR、信封和
     `object_id`，kind code 按 ADR 0013 §1。
   - 按块受检解码的 `Program`：从块来源按需加载并校验。
   - 运行时：局部/分支结果、单选与多选、`min = 0`、`next`、呈现项与呈现键。
   - 会话：State/Input/提交对象及 `decode_state`/`decode_input`；恢复不重放，另有可选的
     `verify_path`；临时 JSON 会话导出。
   - view 与生成的 JSON Schema。

   R1 的执行代码删除。
3. **本地内容方** `narrata-content-local`（新 crate，放在 tooling 下）：
   - 内容包格式（ADR 0013 §9）。
   - 批量 `resolve` 得到 `ok`/`unavailable`/`incompatible`，实现
     [内容引用契约](../../../contracts/content-references.md)。
   - 按命名参数格式化；`ref` 参数一并解析。
   - 导出内容大纲。
4. **工具 `narrata-node-tools`**：
   - `compose`：写打包构件、lock、分析输出，并追加墓碑。
   - `ids`：为缺少 `id` 的条目铸造 UUIDv7 并写回源稿。
   - `inspect`：输出人可读的 JSON。
   - `run`：配合本地内容包打印解析后的文字；动作按别名给出。
   - `migrate-r1`：转换源稿，迁移 R1 存档。
   - `schemas`。

   保持 `narrata_node_tools::run(&[String])` 与 `usage()` 的签名：`crates/narrata-cli` 通过它们
   提供 `gamebook` 子命令，而那个目录属于另一个 Goal 的进行中任务，不要改它。
5. **示例作品**：用 `migrate-r1` 转换 `products/gamebook-demo`，之后手工整理：
   - 角色称呼参数 `visitor` 改为 `ref` 类型；
   - 文字放进 `products/gamebook-demo/content/zh-Hans.json`；
   - 示范至少一个局部选择（回应后在同一单元汇合）和一个多选。
   新增选择要放在不改变原有路线的位置。README 改写为 R2 的写法。
6. **Wasm 与阅读器**（Goal `web-and-rezics` 尚未启动。维护者把决定交给 manager，
   manager 决定由本 Goal 一次性认领 `examples/gamebook-web`）：
   - `narrata-nodes-wasm` 暴露打包构件的打开、选择（选项 ID 集合）、checkout、导出与恢复，
     以及本地内容方。
   - 阅读器 worker 加载内容包，批量解析 view 中的引用后渲染，体验与现在一致：标题、段落、
     选项、禁用原因、结局页、历史、变量面板、图检查器。
   - IndexedDB 中的 R1 记录经 R1 存档迁移升级；迁移失败时退回到现有的内存模式并给出提示。
   - Playwright 回归按新流程更新并保持覆盖面。只做适配，阅读器外壳与渲染插槽不在本任务内。
7. **冻结语料**：
   - `fixtures/compat/nodes-r2/`（kernel-and-saves 已同意）：示例作品的打包构件、内容包、
     内容大纲、一个线性和一个带分支的会话导出，以及带 SHA-256 的 `manifest.json`。根目录
     `.gitattributes` 为它加 `-text`；该文件无人认领，作为 OWNER CHANGES 报告。
   - 测试读取 `fixtures/compat/nodes-r1/`（只读，见其 `manifest.json`），证明源稿迁移与两份
     R1 存档迁移的结果一致。

## 证明

测试与实现一起写：

- **属性测试**（proptest 已是 workspace 依赖）：
  - 只改内容包文字或别名，不改变 `artifact_id`、任何块与提交的 ID、State 摘要。
  - 换语言（同一作品的两个内容包）不改变 State 摘要与提交 ID。
  - 编码往返后字节相同，受检解码拒绝被篡改的字节。
- **选择模型**：每条 §4 规则都有正反例。
- **会话**：
  - 恢复后 view 一致；恢复拒绝构件不符、未知 ID 和越界 State。
  - `verify_path` 能发现不可达的状态。
- **R1 迁移**：使用 `nodes-r1` 语料。
- **阅读器**：浏览器回归；还要用 Playwright 截图实际走一遍并查看。

## 怎么做

- 先读 ADR 0013、ADR 0011、[选择模型](../../../contracts/choices.md)、
  [内容引用](../../../contracts/content-references.md)，再读现有的 `model.rs`、`compile.rs`、
  `runtime.rs`、`narrata-kernel/src/codec`。
- 顺序：kernel `content` 类型 → 源稿模型与编译 → 构件编码与 `Program` → 运行时与会话对象 →
  工具与本地内容方 → 示例作品 → Wasm 与阅读器 → 冻结语料。每一步都做连贯的提交。
- ADR 0013 是规范。实现中发现它的缺陷或歧义时：做最小的修正，在同一提交中改 ADR 并说明理由，
  然后写进交接。不要加 ADR 之外的格式选项、抽象层或功能。
- **不在本任务内**，但编码要预留 ADR 指定的字段与变体：
  - 内容大纲诊断，只需能导出大纲；
  - 动态提议的执行，Input 的 `propose` 变体与 Frame 的 overlay 字段号必须预留，解码时以
    `unsupported` 拒绝；
  - 合成作品基准；
  - 发布时布局与瓦片（G-006 在 `narrata-graph` 中做）。

  `compose` 的分析输出只需不含文字，保持阅读器图检查器可用。
- 契约页 `content-references.md`、`choices.md` 在实现后收缩为代码说不了的部分，指向类型与测试。
  ADR 0011 的状态行注明哪些部分被 ADR 0013 取代。
- 根 `Cargo.toml`（workspace 成员）和 `Cargo.lock` 无人认领：做最小修改并报告。


`check:r1` 会对 `packages/narrata/nodes/schemas`、`examples/gamebook-web/src/generated` 和
`products/gamebook-demo` 做 git diff 漂移检查。新增的生成文件也要纳入这个检查：修改
`scripts/check-r1.ps1`，并保证提交后它通过。

已知风险：
- 第一次 cargo 构建要编译全部依赖，只构建需要的 crate。
- `check:r1` 的浏览器回归使用端口 4173。
- 阅读器存档里的 R1 记录来自真实用户，迁移不能丢数据：失败时保留原记录。
