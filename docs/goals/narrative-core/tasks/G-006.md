## 结果

新 crate `packages/narrata/tooling/crates/narrata-graph`：一套 Rust 实现，发布时对叙事图做
拓扑分析、分簇分层布局，并产出细节层级瓦片和语义摘要。它可以在 CLI 中运行，也能编译到
`wasm32-unknown-unknown`。依据是 [图与分析契约](../../../contracts/graph-and-analysis.md)、
[决定 12](../../../product/decisions.md) 和
[图渲染调研](../../../research/2026-10-05-choice-granularity-and-scale/graph_rendering.md)。

**输入**是与节点格式无关的图：

- 节点：16 字节 ID、种类（段落、分支、状态、调用、返回、结局等，用小整数枚举）、所属簇
  （内容单元或图）、可选的作者排序键；
- 有向边：种类为分支选项、next、条件、调用、返回；
- 入口和结局节点。

R2 节点格式正在另一个任务（G-005）中实现，你不要依赖 `narrata-nodes`。等它合并后，
manager 会另派一个适配任务把 `CheckedProduct` 转成这里的输入。

**输出：**

1. **拓扑诊断**：
   - 合并平行边；
   - 从入口的可达性、不可达节点；
   - 死路（非结局却没有出边）；
   - 结局集合；
   - 环与回边；
   - 支配节点与瓶颈（所有到结局的路径都经过的节点）。

   每个节点得到一行分析列。
2. **层级**：先按输入的簇分组。单个簇超过阈值（约 2,000–5,000 节点，取常量）时，在瓶颈或环
   处再切分。
3. **布局**：
   - 簇内做分层布局，可用最长路径或 network simplex 分层、重心法减少交叉、简单的坐标分配；
     选最简单且够用的算法，并说明理由。
   - 簇之间再做一次布局。
   - 每个节点保存稳定的排序键和坐标。
   - **只改动一个簇的内部时，其他簇中所有节点的坐标不变**，用测试证明。
4. **细节层级瓦片**，分三级：
   - 作品级：簇节点与聚合边；
   - 簇级；
   - 节点级：每块约 500–2,000 个元素。

   每个元素带重要度，决定在哪个缩放级别显示标签。编码要求：
   - 列式：坐标、种类、重要度、边端点索引都是小端类型化数组，放在 CBOR byte string 里，浏览器
     可以直接在上面建 `Float32Array`/`Uint32Array`，不必为每个元素建对象；
   - 外层用 `narrata-kernel` 的规范 CBOR 与信封，kind code 取 `0x0120–0x013F`（ADR 0013 §1
     保留），以 object id 命名。
5. **语义摘要**：带版本的 JSON，内容是入口、结局及其分类、每个结局可达的簇集合（路线的结构
   近似）以及瓶颈序列。它不含选择边全集，规模为每部作品几十到几百条事实。实体首次出现需要
   实体模型，目前还没有，留作扩展点。

## 约束

- 满足需求的最小实现。不要做插件化、可配置的算法选择、通用图库适配层，也不要多套布局。依赖
  只加确有必要的；如果引入现成的图算法 crate，说明理由，并确认它能编译到 wasm32。
- 确定性：相同输入得到逐字节相同的瓦片与摘要（禁止依赖 HashMap 迭代顺序与浮点不确定性；
  坐标在编码前定点化或固定舍入）。
- 只在认领路径内工作。根 `Cargo.toml` 的 workspace 成员和 `Cargo.lock` 无人认领：做最小修改，
  并在交接的 OWNER CHANGES 中报告。

## 证明

- 单元测试覆盖：
  - 每类诊断，包括环、不可达、死路、支配与瓶颈；
  - 布局不变量：同层不重叠，非回边的边从上层指向下层；
  - 簇稳定性；
  - 瓦片解码往返与确定性。
- 带合成图生成器的基准：
  - 规模：10k 与 100k 节点，每簇约 20 个选择点，以局部汇合为主，少量跨簇分支；
  - 记录整图分析加布局加瓦片的耗时、峰值内存与瓦片总大小（含 brotli 或 gzip 估计）；
  - 写进 `docs/development/benchmarks/graph-layout.md`，并给出复现命令。

  目标：10 万节点在本机数十秒内完成。达不到时如实记录，并说明瓶颈。
