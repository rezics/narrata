## 结果

用合成作品基准证明 Goal 的规模结果（[GOAL.md](../GOAL.md)，[决定 10](../../../product/decisions.md)），
并补齐运行时按块懒加载缺的部分。

1. **合成作品生成器**，放在新 crate `packages/narrata/tooling/crates/narrata-node-bench`，经
   `narrata-nodes` 的公开 API 编译出打包构件。
   - 规模：10 万选择点，约 5,000 个内容单元，每单元约 20 个选择点，以局部汇合为主（约 95%），
     少量分支选项进入别的段落与图。
   - 结构：多个包，数百到数千个图，经 `call`/`return` 串联，模拟章节。
   - 数据形状参照 [选择粒度调研](../../../research/2026-10-05-choice-granularity-and-scale/choice_granularity.md)。
   - 生成是确定的（固定种子）。
2. **测量**，用计数分配器测分配字节，这是确定的；Windows 峰值工作集只作参考：
   - 打开构件（只读清单）与首屏（清单加首块）的字节数与耗时；
   - 一次游玩（数千次选择，跨越大量图）中，每次 `choose` 的处理时间分布（p50/p99/max）；
   - 峰值内存与同时加载的块数。

   目标：每次选择在本机低于 1 ms；峰值内存与活跃块数成正比，而不是与作品总量成正比；
   首屏只需清单与首块。
3. **懒加载补齐**：`Program` 目前只加载、从不释放。加一个有界的块缓存：
   - 当前栈帧引用的块必须保留，其余按最近最少使用淘汰，上限可配置；
   - 淘汰后再次访问时重新从 `ChunkSource` 读取并受检解码；
   - 测试证明栈很深时也不会淘汰在用的块，淘汰不改变任何结果与摘要。

   块的划分策略（每图一块）不变。基准表明需要切分单个图时，在交接中提出 ADR，不要自己改格式。
4. **Task 与文档**：
   - `scripts/benchmark-nodes.ps1`，并在 `Taskfile.yml` 加 `bench:nodes`（该文件无人认领，
     作为 OWNER CHANGES 报告）；
   - `docs/development/benchmarks/nodes-scale.md` 写复现命令、机器、结果表与结论。达不到目标时
     如实记录瓶颈。
