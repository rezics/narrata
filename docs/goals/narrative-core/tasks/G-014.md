## 结果

把节点会话的提交、存档、恢复、导出与导入改由 kernel 完成。这是 Goal 的耦合约束，也是
kernel-and-saves 验收"节点会话的保存、恢复、导出、导入通过 kernel 完成"的另一半：

- **Domain**：在 `narrata-nodes` 中为节点实现 `narrata_history` 的静态 `Domain`，kind 为
  `0x0110` 提交、`0x0111` State、`0x0112` Input（ADR 0013 §1/§6；kernel 的提交载荷与 R2
  的提交身份逐字节相同，只换容器）。
  - 参照 `narrata_history::testing` 的计数器领域，以及 [ADR 0015](../../../adr/0015-kernel-history-layer.md)。
  - `decode_state`/`decode_input` 已存在：直接接上。
  - `advance` 的 step 闭包调用现有运行时。
  - 已知限制：GC 在 `advance` 中途回收了被复用的转移时，返回 `MissingObject`，重试一次。
- **Session**：会话由 `narrata-history` 驱动，用它的 checkout、分页子节点、存档槽与 checkpoint
  导出/受检导入；不重放的加载与可选的 `verify_path` 用 kernel 的实现。
  - 临时 JSON 会话导出（ADR 0013 §6）保留为只读的导入路径：旧导出与 `nodes-r2` 语料仍能导入。
    新导出使用 kernel 的 checkpoint。
  - 原生端（CLI、测试）用 `MemoryBackend` 或 SQLite 后端。
- **浏览器**：阅读器经 `narrata-storage-host` 的 `CacheBackend` 与
  `packages/narrata/kernel/js` 的 `IndexedDbStore`/`StorageHost` 持久化，并按
  [ADR 0017](../../../adr/0017-browser-storage-host-cache.md) 的协议运行：缺失时加载后重试；
  批次在 IndexedDB 提交后才确认，确认后才发布 view；多标签页冲突要检测出来。
  - 可运行的样板是 `packages/narrata/kernel/js/browser/counter` 及其 Playwright 测试。
  - 阅读器的 store 只放节点 kind，不与旧栈混用（GC 的 kind 注册表尚不支持混合）。
  - 现有的 IndexedDB 记录（R2 临时导出与 R1 备份）经导入路径升级，失败时保留原记录并退回
    内存模式。
  - Goal `web-and-rezics` 尚未启动，阅读器仍由本 Goal 一次性认领，只做持久化层的改动。

- **规模集成**：G-012 已合并有界块缓存与帧固定（`program.rs` 中的 pin guard），但运行时还没用上。
  - 在 `runtime.rs` 的 call/return 和会话生命周期中持有与释放固定，保证栈上的块不会被淘汰。
  - kernel 历史层去掉了会话只能保留 512 个提交的限制后，补上长游玩测量：在
    `narrata-node-bench` 中跑数千次选择、跨越大量图，记录每次选择的 p50/p99/max、峰值内存与
    活跃块数，并更新 `docs/development/benchmarks/nodes-scale.md`。
  - 目标是每次选择低于 1 ms（目前 p99 约 1.1 ms）。不达标时，找出是块的同步加载与解码，还是
    运行时本身，并做必要的优化：预取下一批可能进入的块是首选，因为宿主可以异步预取。

## 证明

- 领域测试：
  - 选择、checkout、在同一父提交上重复同一 Input 时复用提交；
  - 带提议的路径；
  - 存档槽重开后 view 一致；
  - checkpoint 导出后受检导入；
  - 篡改的对象被拒绝；
  - `verify_path`。
- `nodes-r2`、`nodes-r2-proposals` 冻结语料仍能导入，结果与以前相同。新的 kernel checkpoint
  冻结到 `fixtures/compat/nodes-r2-history/`（带 SHA-256 的 manifest，根 `.gitattributes`
  加 `-text`）。
- 浏览器回归：
  - 刷新后继续；
  - 两个标签页冲突；
  - 清除缓存后从 IndexedDB 恢复；
  - 旧记录升级。

  另外用 Playwright 截图走一遍阅读流程。

## 约束

- 不修改 kernel 的 crate 与 `packages/narrata/kernel/js`；需要的改动作为提议写进交接。
- `program.rs` 的缓存与固定接口已在 main 上，需要改它时做最小修改并报告；
  `lib.rs` 只加导出行。
- ADR 0013 §6 的"临时容器"改为指向 kernel 的 checkpoint，在 ADR 的修订节写明。
