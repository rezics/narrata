## 结果

`compose` 在发布时做完 ADR 0013 §4 与 [ADR 0016](../../../adr/0016-graph-publication-format.md)
要求的事，产出宿主能直接使用的诊断、瓦片与摘要。

1. **内容大纲诊断**（ADR 0013 §4）。内容方能提供大纲时（本地内容包的大纲已能导出，
   见 `narrata-book outline`），`compose` 必须对照大纲报告：
   - 锚点不存在；
   - 违反正文内顺序约束（`body.first ≤ P(0)`，回应严格落在 placement 与 rejoin 之间，
     `rejoin ≤ 下一个 placement`，都在正文切片内）；
   - 标记块与 `placement` 不一致、重复或指向未知选择点。

   这些是诊断而不是错误，退出码不变，写进分析输出。检查逻辑放在 `narrata-nodes` 的
   `outline.rs`，纯函数、不读文件；`compose` 负责读大纲。没有大纲时跳过并说明。
2. **图分析接入 R2**：
   - 适配器（`publish.rs`）把 R2 程序转成 `narrata-graph` 的结构图输入：节点、边的种类、
     作者簇（内容单元，没有正文的节点归入所在图）、入口与结局；
   - `compose` 写出瓦片索引、各级瓦片（以 object id 命名）与语义摘要 JSON，摘要的
     `artifact_id` 由适配器填入；
   - 拓扑诊断（不可达、死路、环、瓶颈）并入 `compose` 的诊断输出。
3. **标签表 `0x0124`**：在 ADR 0016 的修订节定义它的形状：`NodeId` 到 ADR 0013 `ContentRef`
   标题的映射，按簇分表，用规范 CBOR 编码，带受检解码。实现放在 `narrata-graph`，它此时可以
   依赖 `narrata-kernel` 的 `content` 类型。冻结一个小语料到 `fixtures/compat/graph-v1-labels/`，
   带 SHA-256 的 manifest，根 `.gitattributes` 加 `-text`。
4. **示例作品**：`products/gamebook-demo` 重新 compose 后提交新的分析输出。原来的
   `story.nar.analysis.json` 如果被新输出取代就删掉，并确保 `check:r1` 的漂移检查覆盖新文件
   （`scripts/check-r1.ps1` 无人认领，最小修改并报告）。阅读器的图检查器属于 Goal
   `web-and-rezics`，不改，只要它继续能用。
