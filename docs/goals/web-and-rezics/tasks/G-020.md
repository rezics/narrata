## 结果

写 `docs/adr/0021-<名称>.md`（状态 Proposed），把[决定 15](../../../product/decisions.md#15-服务器存档实现同一个存储契约)
变成可以实施的设计：登录用户的 Narrata 存档保存在宿主服务器上，服务器实现
[窄存储契约](../../../adr/0012-narrow-storage-backend-contract.md)，浏览器经
[ADR 0017](../../../adr/0017-browser-storage-host-cache.md) 的批次协议增量读写。只写 ADR，
不写代码。manager 评审后据此派发实现任务。

ADR 必须对下面每一项给出决定和理由：

1. **拓扑。** 浏览器的 IndexedDB 与服务器库的关系：浏览器直接以服务器为宿主（IndexedDB 只做
   离线缓存），还是 IndexedDB 为本地库、后台与服务器同步。覆盖离线阅读、首次登录时合并匿名
   本地存档、切换账号与登出、删除存档。
2. **传输与寻址。** 协议消息如何由宿主的网络传输承载；库如何寻址（宿主把"用户 × 作品"映射到
   库，Narrata 只见不透明句柄）；身份、权限、配额由宿主负责，Narrata 规定宿主必须检查的上限。
   如需新消息或新协议版本，给出形状与冻结向量计划；能沿用 ADR 0017 版本 1 的就沿用。
3. **服务端语义。** 宿主在一个数据库事务中应用落盘消息（核对库标识与修订号、对象
   put-if-absent、写键、推进修订号）与回答加载请求，与 IndexedDB 宿主一致。给出 PostgreSQL
   参考 DDL（库、对象、键三张表），证明 `bytea` 的排序与契约字典序一致，说明修订号的类型与
   JavaScript 数字上限（ADR 0017 拒绝超过 `2^53 − 1`）。
4. **多设备冲突。** 两台设备从同一修订号写入时如何处理；读者看到已确认的选择不得被静默丢失，
   未确认的部分如何重放或呈现给读者。
5. **体积与保留。** 每个库如何保持有界：[浅历史](../../../adr/0019-shallow-history-bundles.md)、
   保留策略与 GC 由谁在哪里运行（浏览器经协议、或服务器上用 Node 运行 Wasm）。
6. **按库迁移。** 决定 15 承诺 Narrata 的结构变化由 Narrata 代码逐库迁移：库的布局版本
   （[ADR 0014](../../../adr/0014-save-engine-key-layout.md) 的 `meta/layout`）落后时谁、何时迁移，
   如何分批、断点续跑、与在线写者并发（CAS），旧证据如何保留以便回退。第一阶段版本互相兼容
   （决定 17），实现可以等第一次布局变化时再做，但机制在本 ADR 定下。
7. **验收方式。** 一致性套件（TypeScript）如何对内存、IndexedDB 与 PostgreSQL 实现运行；
   本机没有 Docker，PostgreSQL 语义用 PGlite（Wasm 版 Postgres）测试是否足够，不够时的替代。
8. **实现计划。** 列出实现任务：每个任务的路径、依赖、检查与冻结语料；以及对
   [REZICS 集成](../../../integrations/rezics.md) 能力请求 R6 的改写文本（manager 合入）。

## 约束

- 满足以上各项的最小设计。不设计新的存储后端抽象、不加能力选项、不碰对象与键的编码；
  契约本身的变化必须单独论证。
- 只依据代码中实际存在的接口写；引用函数与类型时核对它们在 worktree 中存在。
- ADR 控制在约 300 行以内，风格照 ADR 0017：决定与理由，不写教程。
