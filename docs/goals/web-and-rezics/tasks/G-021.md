## 结果

写 `docs/adr/0022-<名称>.md`（状态 Proposed）：REZICS 的编辑器（浏览器）与发布服务（Node/Bun）
如何用 Narrata 创作和发布 Gamebook，以及发布产出的关系投影与读者地图。只写 ADR，不写代码。

现状：R2 源稿（`narrata-nodes/src/source.rs`，严格 JSON）与 `compile` 只在 Rust 中可用，遇到
第一个错误就停；`compose` 的墓碑连续与 `--locked` 绑定在文件系统的 `ProjectFiles` 上；ID 由
`narrata-book ids` 改写文件铸造；`narrata-nodes-wasm` 只有对已编译包的 `publishGraph`；
发布只写 `.narpack`，没有把清单与程序块拆成独立对象的工具。

ADR 必须对下面每一项给出决定和理由：

1. **草稿记录。** 宿主数据库中的创作单位（能力请求 R4 设想"每个选择点一行"，载荷为 Narrata
   规范格式，选项 ID、来源单元与块、目标单元做成派生索引列）：记录的粒度（选择点、节点或
   段落）、规范编码与版本、派生索引列及其推导函数、记录如何组装成 `ProjectSource`。宿主只保存
   与索引，载荷只有 Narrata 解读。
2. **编辑期接口。** 单条记录的校验、一次返回全部诊断（不再首错即停）、在内存中铸造 ID
   （UUIDv7，决定 3）、以上一次发布为输入保持墓碑连续与锁，不依赖文件系统。
3. **发布接口与产物。** 输入草稿记录与内容大纲（R12），输出对象集合：程序清单、各程序块、
   墓碑集、图瓦片、标签表、语义摘要、关系投影，按内容寻址命名，宿主把它们放进对象存储，
   "作品当前发布"指向哪个摘要。发布诊断（锚点、标记块、不可达等）的形状。
4. **Wasm 模块划分。** 创作与发布代码放进单独的 Wasm 模块或 crate，不让读者端的运行时
   （当前约 960 KB 未压缩）变大；两者在浏览器与 Node/Bun 中的加载方式。
5. **关系投影 v1**（[决定 16](../../../product/decisions.md#16-程序的关系投影进入宿主数据库)）。
   行类型与列：内容单元、节点到单元、单元之间的分支边、入口、结局、路线、簇、首次出现；以
   （构件摘要, 投影版本）为键、只插入；PostgreSQL 参考 DDL 与索引；10 万选择点作品的行数与
   体积估计；投影版本变化时从保留构件重新生成的规则。
6. **读者地图。** 从存档求已访问集合的函数，从投影加已访问集合生成地图的函数；揭示边界
   （已访问单元、可见的下一步、未揭示节点不出现在输出中）；两者都是纯函数，浏览器与服务器
   都能运行。说明已访问集合由读者浏览器上报时的信任问题与宿主的选择（防剧透保护的是读者体验，
   不是安全边界），以及与 REZICS 阅读进度（R1）的关系。
7. **实现计划。** 实现任务的路径、依赖、检查与冻结语料（草稿记录编码、投影行、发布对象集合）；
   对能力请求 R4、R9、R12 的改写文本，以及新增"关系投影表"能力请求的文本（manager 合入）。

作品重新发布时存档如何继续、发布前对存档的 dry-run 属于并行的节点栈作品演化 ADR（0023），
本 ADR 只给出发布接口中供它挂接的位置。

## 约束

- 满足以上各项的最小设计；复用现有源稿类型、编译器与 `publish.rs`，不另起一套格式。说明
  哪些现有格式不变、哪些需要新格式与冻结语料。
- 不设计编辑器界面；REZICS 自己做界面，Narrata 只给无界面的接口与参考阅读器中的样例。
- 只依据代码中实际存在的接口写；引用函数与类型时核对它们存在。
- ADR 控制在约 350 行以内，风格照 ADR 0016：决定与理由，不写教程。
