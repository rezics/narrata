## 结果

实现 [ADR 0022](../../../adr/0022-authoring-publication-and-reader-map.md) §6 定义、
[ADR 0023](../../../adr/0023-node-artifact-evolution.md) 路径比较共用的只读执行轨迹，只做轨迹本身：

- 在 `narrata-nodes` 的执行核心（`runtime.rs`）中加一个默认关闭的 cargo feature（如 `trace`）。
  开启时，每次推进（含 initial）按执行顺序产出事件：经过的 graph/node、呈现的 Segment（单元与
  锚点）及 `Interaction::Finished.body`、选中选项的 outcome/target、branch 去向、call/return。
- 轨迹是只读观测：开启与否，State、提交、摘要与视图都逐字节相同（测试证明）；关闭时没有任何
  额外代码进入构建（`cfg` 门控），`narrata-nodes-wasm` 不开启它，读者 Wasm 的大小不变（构建前后
  对比并在交接中给出数字）。
- 测试覆盖自动经过的多个节点、调用与返回、局部回应与汇合、多选、动态提议、结局，以及事件
  顺序的确定性（相同输入两次得到相同事件序列）。

`visitedFromSave`、读者地图（ADR 0022 §6）与路径比较（ADR 0023）是后续任务，不在这里实现；
把轨迹 API 设计成它们能直接消费的形状，并在交接中写明用法。

## 约束

- 最小实现：不改存档、提交或任何线格式，不新增持久回执；不改公开 API 的现有签名，新入口只在
  feature 开启时存在。
- 并行任务在同一 crate 中改 `compile.rs`、`check.rs`、`registry.rs`、`source.rs` 与 `lib.rs`，不要碰
  它们；轨迹放在 `runtime.rs` 或其子模块 `runtime/` 中。
