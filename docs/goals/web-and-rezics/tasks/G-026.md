## 结果

实现 [ADR 0021](../../../adr/0021-server-save-storage.md) 实现表的第一行"宿主一致性与边界收紧"：

1. **put-if-absent。** `IndexedDbStore.persist()` 用 `objects.put()`，Rust 的参考 `MemoryHost`（
   `narrata-storage-host/src/testing.rs`）用 `insert()`：面对同摘要不同字节的落盘消息都会覆盖。
   两者改为契约规定的 put-if-absent（已有对象保留原字节）。
2. **TypeScript 一致性套件。** 一个工厂返回现有 `CacheStore`，加建库、重开、清除的测试夹具；同一组
   断言分别运行 TS 内存参考宿主（测试夹具，不是产品后端）与 `IndexedDbStore`（fake-indexeddb
   与真实 Chromium）。断言照 ADR 0021"验收"一节的共同部分：逐字节排序与分页、空区间、同一起始
   状态与消息得到相同结果、对象 put-if-absent、缺条目 null、键与库修订号、删除重建无 ABA、两个
   写者同 base 只成功一个、多批落盘整体原子、只在提交后确认、库替换后的旧请求失败、坏 CBOR /
   列表 / 摘要长度 / 数值全部拒绝、重开保留状态。套件导出成可复用的形式，后续的 PostgreSQL
   参考宿主直接运行它。
3. **上限。** 宿主在解码与写入前检查 ADR 0021 上限表中适用于浏览器宿主的部分，不信任调用方
   已经检查过；超限整次拒绝。

沿用 `test/protocol.test.ts`、`indexeddb.test.ts`、`host.test.ts` 的风格；Rust 侧的
`CacheBackend` 与 `MemoryHost` 测试继续校验相同协议。

## 约束

- 不改协议 v1、IndexedDB 布局与冻结的 `fixtures/compat/browser-storage-v1/`；新增测试向量放在
  测试里，不新增冻结目录。
- 不做 PostgreSQL 宿主、网络传输或阅读器生命周期，它们是后续任务。
- `packages/narrata/web` 在构建时复制 `packages/narrata/kernel/js/src`；改动后确认它的检查仍通过，
  但不改 Web 包。
