## 结果

实现 [ADR 0021](../../../adr/0021-server-save-storage.md) 实现表的第二行"PostgreSQL 协议参考宿主"：
宿主服务器上处理 ADR 0017 v1 `load` 与 `persist` 消息、把库存进 PostgreSQL 的 TypeScript 参考
实现，以及证明它正确的检查。

1. **参考宿主**（`packages/narrata/kernel/js/server/`）。依赖一个最小的事务化 SQL 接口（宿主
   传入，例如 `query(text, params)` 加事务边界），不绑定具体驱动；REZICS 可以用自己的 `pg`
   连接与事务照用或照抄。`persist` 与 `load` 严格照 ADR 0021"PostgreSQL 参考布局与事务"一节：
   库行 `SELECT ... FOR UPDATE`、核对库标识与 base、对象 `INSERT ... ON CONFLICT DO NOTHING`、
   键写入带批次修订号、同一事务核对配额并推进库修订号、提交成功后才回复已持久化；加载在
   REPEATABLE READ 只读事务中完成；`bytea` 参数化、不经文本或 locale 排序；修订号经整数与范围
   检查后才转为 JS number。解码前检查上限，复用已有的 `limits.ts` 与协议编解码。
2. **参考 DDL**：ADR 0021 中的三张表，作为文件随参考宿主提供，宿主自己用编号 SQL 安装；包
   不执行迁移。
3. **一致性。** 用 `test/support/conformance.ts` 的同一套断言运行参考宿主：本机用 PGlite（新增
   开发依赖，记入工具链），另加 ADR 0021 中 PGlite 能证明的部分（DDL 与约束、排序边界 `00`、
   `7f`、`80`、`ff` 与前缀、事务中途失败回滚、顺序 CAS）。
4. **真实 PostgreSQL。** 同一套件在设置了连接串环境变量时对真实 PostgreSQL 运行，并加 PGlite
   证明不了的双连接竞争（两个写者同 base、加载与写入交错）；未配置时明确报"跳过"，不算通过。
   在 `.github/workflows/ci.yml` 中加一个 `ubuntu-latest` job，用 `services: postgres` 跑它。
5. 新 `task check:server-storage`（类型检查、PGlite 套件、有连接串时的实库套件）记入工具链。

## 约束

- 只做参考宿主与检查；网络传输、认证路由、阅读器生命周期、GC 维护入口是后续任务。不把参考宿主
  加进 `@rezics/narrata` 的导出（Web 包的子路径由后续任务统一安排）。
- 不改协议 v1、对象与键的编码、IndexedDB 宿主与冻结语料；不新增冻结目录。
- 不在本机安装 PostgreSQL 服务或 Docker；本机只跑 PGlite，实库部分在 CI 中证明。CI 改动只能在
  manager 推送后验证，交接中写明预期结果与本地能证明的部分。
