## 结果

实现 [ADR 0022](../../../adr/0022-authoring-publication-and-reader-map.md) §3、§5 与 §7 实现表的第二行，
在上一步的 `narrata-authoring` 之上：

1. **发布**（§3）：`publishRecords(records, outlines, previous, mode)` 组装、校验、内存 compose，
   调用现有图发布与 `publication_analysis`，把程序拆成独立对象（清单、各块、墓碑集、可选名字表），
   与图瓦片、标签表、语义摘要、关系投影片及其索引一起组成发布对象集合；生成集合描述 v1 与
   `publication_id`；诊断报告 v1；"编译成功"与"可切换发布"是不同的结果。抽出共用的对象编译
   路径，用现有 `Program::from_manifest` 与 `verify_artifact` 复核全部对象；旧 `compile` 与打包
   行为保持不变。图发布核心（现 `narrata-node-tools` 的 `publish.rs`）移到能编译到 wasm32 的
   位置供 `narrata-authoring` 使用，CLI 成为文件适配器。集合描述中为 ADR 0023 的可选 `evolution`
   角色留出位置（本任务不生成它）。
2. **关系投影 v1**（§5）：`projectRelations(checkedProgram)` 纯函数，八种行类型、排序、4 MiB 分片、
   索引与受检读取，照 ADR 的推导规则；ADR 中的 PostgreSQL 参考 DDL 作为文件随 crate 提供。
3. **冻结语料** `fixtures/compat/publication-v1/` 与 `relations-v1/`：示例作品"山口来信"的全部发布
   对象摘要、集合描述、投影分片与行；两次生成逐字节相同；测试旧构件重建、不同输入顺序同摘要、
   正文独立、坏引用 / 重复 / 缺片拒绝、新旧发布隔离与幂等、对象总量超过 64 MiB 而单个对象合法
   （用合成作品）。
4. 用合成作品（`narrata-node-bench` 的 10 万选择点生成器或同规模的输入）实测关系投影的行数与
   规范 JSON 字节，与 ADR 的估计并列写进交接。

## 约束

  不变，只新增发布对象集合。
