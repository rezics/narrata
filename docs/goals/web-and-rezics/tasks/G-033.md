## 结果

实现 [ADR 0023](../../../adr/0023-node-artifact-evolution.md) 实现表的第一行：作者重新发布后，节点栈的
存档如何继续，在 `narrata-nodes` 内完成。

1. **声明与描述符**：`RecoveryDeclarationsV1` 与 `EvolutionDescriptorV1` 的受检类型、严格 JSON 与
   规范 CBOR、`MigrationId`，以及它们的 schema（照 ADR"恢复声明与有损结果"一节的格式、排序与
   上限）。
2. **自动迁移**：按稳定 ID 保留状态、用目标程序的 `decode_state` 受检重建、规范往返；墓碑位置的
   根恢复；有损报告；`Unknown` 不当删除。
3. **路径比较与重放分歧**：在目标构件上影子执行记录的选择与提议，比较语义状态与控制轨迹（用已
   合并的 `trace` feature，见 `runtime.rs` 的 `trace_initial` / `trace_apply`），在第一处分歧停止；
   按段审计已有迁移；`Equivalent` / `Diverged` / `Unverified` 与资源上限。
4. **协调与会话**：把节点域与描述符注册到 kernel 的 `ArtifactRegistry` / `MigrationRegistry`，经
   `History::dry_run_migration` / `apply_migration` 写 `MigrationInput`；以 active cursor 为目标 Ref
   做 CAS；跨迁移边的历史、回退与呈现按每个提交的构件解析；继续旧版本按存档的构件摘要打开。
5. **评估与应用的结果类型**：ADR 中的 `AssessmentV1` 与 `ApplyV1`（Rust 类型与 JSON schema），
   计划绑定与确认失效。升级策略由宿主决定，Narrata 从不自行升级。
6. **冻结语料** `fixtures/compat/nodes-evolution-v1/`：照 ADR"实现顺序与兼容证据"列出的场景
   （至少：未走路径的规则变更自动迁移、内容与别名不换构件、改目标后汇合仍检出首处分歧、多选重排、
   提议 ID 保持与碰撞拒绝、删除当前位置 / 下层 call / 结局的根恢复、无声明或冲突声明或变量变型
   拒绝、浅历史未核对、已迁移后再发布、旧存档继续）；两次生成逐字节相同。
