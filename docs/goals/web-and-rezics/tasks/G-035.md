## 结果

完成 Goal M1 的在线存档、账号/会话生命周期与按存档身份恢复构件。沿用 ADR 0017/0021、决定 15；
不增加 HTTP 协议、数据库布局、整包存档或登录离线同步。宿主注入认证后的 CacheStore 传输与库生命周期
回调，继续复用 PostgreSQL 参考宿主与一致性套件；不重写 SQL，也不改 REZICS。

已有 StorageHost 保留未知写入的原始 flush、阻止新操作并提供 retryPending；Book.retrySave 与
显式 reload 已接线。真实 IndexedDbStore 对丢回执后的同字节重试可返回 Conflict，不能把它当作必然
丢失或必然成功。本任务在此基础上完成下列旅程，不重新构建这层机制。

1. 公共在线会话包装绑定一个不可变的已认证库实例，区分 saved、pending/unknown、conflict、quota、
   unavailable、closed。只有持久化确认后宣布 saved。未知结果保留本次候选提交并重试原字节，绝不
   重放选择。冲突重载后，用 Narrata 受检的同 execution durable roots/history 查询证明候选仍被保留；
   仅对象存在或库 revision 增大不足以证明保存成功。核实失败/缺对象/资源限额仍为 unknown，保留原持久进度。
2. quota/明确拒绝后允许安全重载。关闭和账号失效在调用边界立即拒绝新操作，再排空/释放旧句柄；
   每个异步回包检查代次，不能把前一账号的内容或成功状态写入新会话。新账号新包装，不能重定向旧 handle。
   删除回调使用已观察的 store ID/revision；关闭旧库后迟到重试不可重建它，重新打开新库必须有新 StoreId。
3. 新增只读存档定位 helper：用既有 layout/ref/commit codec 找 execution 的当前 cursor 与精确 artifact；
   不通过会初始化空库的 History::open 假装只读。无 active cursor 才表示新旅程；缺失/坏对象是另一类失败。
   宿主注入按 artifact 查清单/名字/块的加载器；先核对清单身份，整个旅程捕获同一构件的块加载器。
   只有新 execution 才读作品当前发布。A 运行中切 B 不混装；旧 execution 恢复 A，新 execution 进入 B。
4. 从正式 tarball 完成模拟在线宿主旅程，包括保存后丢响应、相同字节重试、另一设备在候选之后继续、
   候选对象存在但没有同 execution 根、核实读失败、CAS 冲突、配额回滚、关闭中迟到响应、账号切换及
   删除/新建后的旧写入。浏览器参考体验显示可理解的恢复动作，失败不冒充结局或删除原进度。
   参考宿主可以注入内存/IndexedDB/PostgresStore 传输以隔离客户端行为；服务端事务语义继续由原套件证明。

类型、受检输入、资源预算和行为测试随实现交付；调用边界本身不是新的持久格式，若确需改变现行格式，
先交接具体 ADR 需求，不偷偷拓展交换字段。原生内容 adapter 已有独立入口，账号切换应调用其 clear 或
通知宿主失效；不把正文存到会话。保持 reader/authoring 分离和旧公开入口兼容。
