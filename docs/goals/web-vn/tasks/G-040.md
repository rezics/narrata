## 决定需要回答什么

- 从真实 SourcePlan/Plan、State/View、Session/输入/编译及 Web public API 约束选一条最小可行路线。
  比较第一方节点语义扩展与复用现有 lowering 的代价并作出选择；不要只列选项，也不要为两个方案都搭实现。
  不新增平行的通用 VM、插件锁或运行时工厂；不要把未受检的特殊全局变量约定当作类型化 VN 契约。
- 逐句对白、说话者、选项、分支/汇合及场景切换的确定输入与 safe point：何时提交、何时能推进、
  stale/重复输入怎样拒绝；保存、回退、分支和重开须恢复语义位置，不重放所有动画或外部副作用。
- 可恢复呈现状态与逻辑游标的关系：背景、角色层、音乐/语音的含义、替换/停止、场景边界及恢复策略。
  明确首个音轨重启/seek 策略和用户开启声音的边界；不承诺采样级同步或复杂导演时间轴。
- 正文/说话者名称/选项文字仍为宿主内容引用，媒体也只存引用；授权地址、DOM/播放器句柄、解码缓冲
  属于播放端/宿主，不进入持久叙事状态。当前文字 payload 不能靠不安全断言变成媒体 API。
- 资源准备与叙事提交分开：当前场景/候选走向的有界预取、取消、失败重试、释放和缓存身份，
  未就绪时可见行为，重试不重复叙事输入，逻辑 A 与新发布 B 不混装，清缓存不删未同步存档。
- 决定需要哪些实际保存/交换格式变化及原因；给出旧 Gamebook 的明确读取/迁移路径、版本边界和
  新冻结语料计划。先作决定再实现；不要改旧 corpus，不放宽受检解码或确定性。
- 对照完整 VN0–VN3，列出后续可独立验收的最小实现切片及确切源码归属、必须覆盖的行为断言。
