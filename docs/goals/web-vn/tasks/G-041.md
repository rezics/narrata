## 原生交付

- 在现有 R2 Node 路线上实现有类型的对白和场景语义。每句是独立 safe point，输出正文/可选说话者引用；
  Advance 与 Choose 区别明确，绑定期望 Commit 和当前交互身份；有效输入最多消费当前一句。
  Branch/Mutate/Call/Return 和稳定 ChoicePoint/Option 身份继续复用。
- 场景是随 Commit 恢复的完整视觉目标：背景、稳定身份和层序的角色图层；正文/名称仍为内容引用，
  媒体为受检、带不可变版本身份的独立引用。错误资源类别、坏引用和不一致状态在检查边界拒绝。
  不把资源语义藏在未验证字符串或任意 JSON/global 约定里。
- 持久音乐的替换/停止/跨场景延续与当前行语音意图可确定执行。保存/checkout/重开恢复相应目标，
  不重放旧动画/宿主副作用；音轨从头重启是播放器策略，本任务只暴露准确的逻辑意图。
  网络 URL、凭据、DOM/播放器句柄、解码缓冲、播放头、手势授权与解析出的内容字节不入持久叙事状态。
- 按 ADR 区分同父状态的确定转移复用、游标已移动后的 stale、未知落盘重试原字节。
  不为本切片增建 RPC 幂等服务。缺必要逻辑块前不能提交半步，加载/重试不能重复推进。
  正文/媒体解析就绪不作为原生叙事提交的前置。
- 保留 Gamebook format2/schema1/GAMEBOOK_REVISION2 的原编译/写/读路径和现有对象字节、View 语义。
  VN source3 与实际新载荷 schema2 必须显式 opt-in/受检分派；不能只替换全局版本常量。
  当前 NodeDomain/schema 注册若确有通用适配缺口，仅做维持同一 Session/容器所需的最窄改动。
  不改变通用 Commit/Checkpoint 格式，除非有具体不可行证据并先交 manager 修订决定。
- 保留旧 Gamebook authoring、evolution、maps、维护等消费方的编译和行为。新增闭合 enum 分支导致的
  既有消费方匹配可作最小、明确的能力分派，不能把 VN 假装成 Gamebook 或全局退化旧语义。
  本任务不实现公共 VN Wasm/npm API、浏览器资源 resolver/cache、播放器或作者产品界面；交接其薄接缝。

## 语料与验证

现有 fixtures/compat/** 全部只读。先在 .temp/ 生成和迭代；格式稳定、测试通过后一次性新增
fixtures/compat/nodes-vn-v1/，有可重复的公开工具生成路径和受检读取/执行测试。已冻结文件不覆盖。
新语料应包含 source/program、State/Input、对白/选项 View 引用、场景目标和可导入历史/Checkpoint；
正文/媒体只是外部宿主 fixture，不能把授权地址或解码状态固化进保存格式。

实现与测试一起写，至少证明：

1. 相同已确定身份的源稿及输入轨迹两次生成逐字节相同对象/Commit。
2. 至少三个连续对白逐行停止、带说话者引用，选择分支并汇合，两个场景的背景/角色/音轨意图准确。
3. 每个对白/选择 safe point 保存并冷重开继续；checkout/回退另选分支恢复准确场景，不丢历史或造新结局。
4. stale/重复点击/坏交互身份/坏资源类别及 State/Input 不一致均不产生第二步或部分持久写入。
5. 按需 manifest/chunk 路径只加载所需逻辑，缺块重试保持原确认进度；当前及历史构件不混装。
6. 所有旧 Gamebook corpus、源稿编译字节、原 public View 与现有相关测试继续成立；新未知 tag/schema 稳定拒绝。

通过 Task 槽位先跑相关原生聚焦测试、fmt/clippy与必要 wasm32 编译，再运行受影响的 task check:r1；
若修改 kernel 通用实现或测试则 task check:g5；工具/脚本改动跑 test:scripts，文档跑 docs:check。
完整 gate/浏览器串行 --heavy，不启动独立开发服务器。不要只跑新 happy-path 测试，或用小预算/空断言绕过恢复。
若工具/检查新增或替换，同一变更更新 docs/development/toolchain.md。
