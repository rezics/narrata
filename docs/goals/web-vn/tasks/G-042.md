VN1, not completion of VN1–VN3. Preserve the accepted ADR 0024 and the full Web VN Goal.

Read the Goal/state, ADR 0024, `.agents/skills/typesafe/SKILL.md`, and the manager's

## Public runtime

- Add an explicitly VN-only Wasm facade and checked typed VN inspection model. A Gamebook
  artifact cannot silently become VN, and the existing Gamebook facade/types remain unchanged.
  Generate validators and TypeScript declarations from authoritative Rust/schema definitions;
  the separate VN View is version 1, with a closed discriminated interaction union and a
  required checked scene target for a VN artifact.
- Expose open from a complete pack and from an exact manifest with asynchronous chunk loading,
  inspect, Advance tied to expected Commit and current dialogue identity, Choose, checkout,
  history provenance, save export/restore, durable reopen, retrySave, reload and close. Keep
  Advance and Choose distinct in types and at runtime; all external JSON/bytes must be checked.
- Reuse native Session/history/CacheBackend and the existing host storage confirmation protocol.
  Factor only the narrow common transport/queue/retry code needed by both readers. Preserve
  Gamebook's public API and behavior, including its old save migration path; VN does not need
  an invented Gamebook-to-VN migration or a generic profile/plugin framework.
- Serialize operations, check missing logical chunks before committing, and preserve confirmed
  progress on missing/corrupt chunks. Retry a failed chunk load without consuming a line twice.
  Unknown persistence retries the same pending request bytes; a moved cursor rejects stale
  Advance. Do not discard unconfirmed progress or pending storage bytes merely to get a green
  happy-path test. Keep existing save conflict/reload behavior explicit.
- Support exact historical artifact loading wherever the reused native history requires it.
  Current A and published B may coexist; no lookup by product name or latest-version fallback.
  Keep limits and release semantics of existing program caches. Resource references are typed
  identities only: resolved text/media bytes, authorization URLs and player handles remain host
  owned and are never added to save objects.
- Package export `./vn`, package-relative Wasm location, generated assets, declarations and
  consumer validation must work in browser, Node and Bun as appropriate. Existing root/reader
  imports must not eagerly import VN authoring, player or unrelated optional graph code.

## Evidence

Implement meaningful tests with the code. Through the public VN entry prove at least three
consecutive dialogue safe points, a choice and scene transition, music/voice intent, save and
cold reopen at dialogue and choice, checkout/alternate branch, stale/wrong interaction rejection,
and failed logical chunk retry retaining the original confirmed cursor. Verify current view and
restored artifact identity, not just a nonempty save or successful construction.

Exercise the real storage host seam for one unknown/failed write and retry: observe identical
pending request bytes, one narrative transition and confirmed view matching durable progress.
Use existing failure-injection helpers where they actually cover the VN facade. Ensure close
rejects new calls and releases queued Wasm resources without allowing late loads to advance it.

Add installed-tarball tests for the VN export and assets, including Node/Bun and Chromium.
Keep the existing Gamebook installed consumer assertions intact. Record incremental package
  size and import/request boundaries; do not arbitrarily raise an old Gamebook budget to hide a
regression. Update the relevant budget accounting when a new optional entry is measured.

Run focused native/Wasm/Web/type tests, then the affected `task check:r1` and `task check:web`
through serial `--heavy` slots. Generic kernel changes also require `task check:g5`; repository
scripts require `task test:scripts`; documentation requires `task docs:check`. Update
`docs/development/toolchain.md` if tools or checks are added/replaced. First commit generated
files before a drift gate that compares them to Git, then run the full gate on that fixed source.
