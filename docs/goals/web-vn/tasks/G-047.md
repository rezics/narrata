## Public API and lifecycle

- Add narrow explicit VN facades using existing generated record/report/lock types and
  the generic Preview where suitable. Share small record conversion, handle and Wasm
  initialization helpers as needed; do not copy the full Gamebook facade or add a generic
  dialect framework. Browser loading stays lazy; Node/Bun default Wasm lookup uses installed
  import.meta.url and must work from another cwd without repository or browser globals.
- Full-set validation/preview must select source format 3 and VN semantics. Single-record
  structural checks must not claim complete VN node or project validation. Do not expose
  Gamebook publish/graph/relations methods as VN operations or cast its CheckedPublication.
  The raw VN bridge exposes locked composition but no previous-publication route: do not
  advertise unsupported continuity through copied Gamebook ComposeOptions.
- Preview compiles exactly one checked snapshot. Reports, artifact, manifest, exact object
  reads, names, lock and optional pack belong to that same immutable candidate. A valid
  edited snapshot must produce its own valid candidate while the earlier one remains usable.
  Free/close behavior must be explicit and idempotent; no call into released Wasm memory.
  A host can open the exact candidate with the public VN reader using its manifest/objects
  or pack. Compilation/preview itself never writes a formal publish pointer or reader save.
- Keep content and media as references. Author source/data are checked in Rust, not granted
  semantic types by unchecked casts. Reuse authoritative generated definitions and existing
  checked-boundary patterns. Avoid new handwritten duplicate result DTOs and hidden imports
  of unrelated Gamebook subsystems in the VN-only facade.
