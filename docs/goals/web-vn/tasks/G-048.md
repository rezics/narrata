## Result

Expose the accepted native Session dependency projection through a narrow, versioned,
read-only VnBook Wasm API and checked JSON boundary. This enables a later public reader
bridge and bounded host preparer. It is not full VN2 or a media cache implementation.

Read Web VN Goal/state, ADR 0024, .agents/skills/typesafe/SKILL.md, native dependency.rs and
its 17 tests, and the current VnBook/NodeBook/HostChunks transport. G-047 owns Web and the
reference publisher. Do not edit Web, its generators/limits or the product. This task owns
only the listed Wasm crate and new schema/ADR/corpus paths. Old fixtures/compat are read-only.

## Contract and implementation

- Write ADR 0025 before implementing the new exchange shape. Reuse existing immutable
  program formats and native query; do not add a VM, unchecked-State input, durable object,
  source/State/Input/Commit/checkpoint field, plugin system or narration/media bytes. Explain
  that this is the first query format, supports its checked v1 read path and rejects other
  versions, while all old Gamebook/VN formats and methods retain their existing readers.
- The actual consumer needs exact artifact/cursor provenance, graph object identities,
  role-preserving content/media references, checked limits/work accounting and explicit
  truncation/source errors/unknowns. Define a small closed v1 request/result DTO over those
  facts. Keep future conditional/assignment/call results conservative; complete enumeration
  is not an exact future-state prediction. This is an incremental dependency set over the
  current View's retained scene resources, not a replacement full scene target.
- Invoke Session::dependency_projection only from the owning checked VN safe point. Mirror
  normal view/readiness handling, including pending/unknown storage outcomes; never invent
  a confirmed future cursor. Current Advance and enabled choices must work with all five
  native bounds. Invalid external limits, tags, refs, versions and inconsistent result data
  are rejected by an authoritative Rust decoder. Derive the dedicated JSON schema from Rust
  definitions and test it; do not change the old BookView or VnView v1 schema.
- No automatic network/chunk-fetch loop here. A cold future graph produces explicit partial
  unavailable/object information. Query I/O must not later force an optional lookahead fetch
  ahead of a narrative input. In particular HostChunks::load writes a pending request even
  when native projection turns its error into a truncation: isolate/restore that transient
  request state so this query neither steals nor leaves a spurious mandatory program request.
  Preserve any earlier ordinary operation request. Do not call NodeBook::finish in a way
  that clears supplied bytes belonging to another operation. Keep this mechanism local and
  bounded to the query's current artifact; no scan of every registered historical artifact.
- Reuse bounded graph cache/ownership behavior, preserve actual source error plus exact object
  identity, and keep storage requests/refs/history/state/visits unchanged. No prefetch pins,
  resource resolver, DOM/audio or bytes/credentials in the result. Free/closed-handle behavior
  follows existing Wasm conventions. Report any minimal native-crate change actually needed
  rather than editing another task's or unclaimed files silently.
