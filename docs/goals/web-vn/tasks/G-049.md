## Result

Deliver the public VN dependency bridge and a usable bounded candidate-resource preparer
that actually reuses prepared resources with the public player. Cover the complete VN2 SDK
behavior, including cross-graph lazy delivery, cancellation, retry, resource release and
immutable A/B isolation. Reference-host wiring and final package-wide handoff can follow
integration, but do not substitute a same-graph-only or fetch-and-discard demonstration for
the preparer. Never mark the entire Goal complete.

Read this Goal/state, ADRs 0024/0025, typesafe and external-content-value skills, the accepted
VnBook.dependencies/corpus, RuntimeVn/RuntimeTransport and public vn/player code. The last

## Reader and query

- Add typed checked public query access with exact artifact/cursor provenance, all five
  limits and explicit partial/truncation/unknown data. Reuse the frozen v1 request/result;
  no external unchecked State or invented future View. Query only a confirmed owning reader
  point, or explicitly reject stale/pending/unknown state. Do not interpret complete as a
  predicted branch or a complete future scene: current View resources remain owned.
- Use a VN-only reader Wasm build with vn-dependencies enabled, from the SAME native stack,
  so Gamebook root/reader retains its current no-default-features module and physical size
  ceilings. One runtime per reader; no second VM or full-history clone as a shortcut. Account
  for the optional VN asset and JS once with measured budgets, and prove the Gamebook first
  screen does not fetch it. Existing custom loader and exact historical artifact behavior
  must keep an honest matching-module contract.
- Optional logical fetch/prepare I/O must not hold the narrative input queue. A delayed
  optional graph request cannot block Advance along an already-available route. Do not steal
  mandatory requests, drop another operation's supplied bytes or install bytes into freed
  Wasm. Bound cumulative retries/objects/bytes, not just one native invocation's counters.
  Keep temporary logical inputs owned, bounded and releasable. Small native/Wasm support
  changes are in scope if necessary; do not build a generic interpreter/graph framework.

## Preparation and cache lifecycle

- Collect useful direct-candidate logical/content/media dependencies, including cross-graph
  scenes, and prepare media with existing checked resolver/presenter contracts. Roles/ref
  versions remain host-owned. Surface future content refs without fabricating dynamic args.
  Host variant selection for hints must be explicit; never pass a made-up future View to an
  existing selector. A changed eventual variant safely misses the prepared cache.
- Prepare without advancing/choosing, writing saves, changing the displayed scene or playing
  future music/voice. Warmed resources must be consumed by the player rather than fetched
  and decoded again. Never share one mutable audio playback timeline across active readers;
  use owned presentation leases or safely separated decode/playback resources.
- Bound concurrent work, requests, encoded/decoded bytes, retained and active resources.
  Count actual live unions including current/reused resources, with no double charging or
  forgotten optional audio. Partial/truncated/unavailable preparation is explicit and does
  not pretend the story ended or block a muted playable scene.
- Cancel/ignore stale jobs on input, cursor/artifact, variant, session, account/auth/content
  scope and close. Late results release exactly once and cannot republish saved/ready over
  saving/unknown status. Resource retry does not reapply a story input; unknown storage still
  uses original-byte retry/reload. Cache cleanup cannot touch unsynchronized narrative saves.
- Reuse immutable same-revision assets across A/B only when provider, variant and authorized
  content scope match. Changed bytes use a new version; no latest fallback or mixed A/B
  graph objects. Authorization/context changes do not resurrect old handles.
