## Result

Add a real host-owned draft-editing flow with immediate isolated preview to the existing VN
reference application, using the accepted public vn/authoring and vn/player APIs. The author
can change real dialogue plus speaker or scene choice, see that checked candidate rendered,
and play its branches/scenes/endings. This closes the interactive editing gap in VN3; final
VN2 wiring and fixed-package acceptance still follow. Do not build a complete editor product.

Read Goal/state, ADR 0024, typesafe and external-content-value skills, the relevant frontend
testing/debugging and React performance skills, and actual accepted public VN authoring and
reference host code. This is a targeted addition to an existing app, not a restyle of its
accepted reader. Preserve the reader's cinematic layout, 13 journeys and default first-screen
lazy behavior. Use an explicit optional author route/mode and lazy-load the compiler there.

G-049 independently owns SDK/preparation code. Do not edit packages, Taskfile, product source,
published object/media/content files or toolchain docs; no new dependency/tool by default.
If a shared helper is needed, extract a small host adapter within your example's scope rather
than clone the whole player or create a new SDK API. Refactor reader host code only if needed
to share its checked text/media/browser adapters, preserving its behavior.

## Author and preview behavior

- Load the real host project/records and content references. Use public split/check/preview,
  never raw Wasm, the Rust demo emitter, a fake Gamebook publication or hardcoded preview
  state. A full record-set check proves VN semantics; render actual diagnostics on failure.
- Provide simple usable controls for at least a real dialogue line and speaker or scene
  background. The host owns text and localization: editing body content updates its host
  draft resolver and reference revision/snapshot. Do not put resolved body bytes into Narrata
  node/state fields or mutate bytes under a supposedly immutable revision.
- A successful edit produces a fresh valid checked candidate and its matching reader. The
  visible preview must use exactly that candidate's artifact/objects and the matching host
  content/media scope. Rapid edits or late resource completions cannot reinstall an older
  candidate. Keep old preview resources owned until swap, then release/close them.
- Use an isolated ephemeral reader/session for preview. Compilation and preview do not
  publish, update the formal host pointer, overwrite the reference source/files, or write
  the formal reader's saved progress. Free candidates only after dependent readers close;
  failure or disposal cannot leave live Wasm/media handles or call freed objects.
- Changes appear immediately or with a short, clear preview action/debounce. Avoid a fake
  JSON debug panel in place of author controls. Handle loading, errors and empty input with
  useful audience-facing copy. Retain 44px touch targets, keyboard labels, phone fit and
  readable layout. No visible internal artifact/commit telemetry unless useful to authors.

## Evidence

Add a dedicated capability-named Playwright authoring spec in the existing automatic test
directory. In actual desktop and 390px browser flows: enter author mode, edit real prose and
speaker/scene, observe a new valid candidate and changed rendered output, play forward and
choose a branch to an ending, make another edit, and recover from invalid/empty input or
resource failure. Test rapid edits and close/reopen/disposal without old results resurfacing.
Record exact candidate identity privately in test hooks, not a public debug UI.

Start with a normal saved reading position, enter/edit/play preview, return to reading and
prove its saved bytes/cursor and formal publication identity remain unchanged. Default reader
mode must not fetch the authoring module. Use screenshots and actual interaction evidence,
not just test names. Inspect desktop/phone screenshots and fix real visual/overflow defects;
retain .temp evidence as this Goal's QA output. Do not regenerate production media assets.

Run fast example types/build, then serial-heavy task check:vn from this checkout, including
old reader and new author journeys. Public SDK code stays read-only. Commit coherent source
and hand off exact tests, screenshots, request behavior and lifecycle limits. Use
gpt-6-luna/high, no subagents, rebase/push, registry or REZICS edits. Do not call this the
whole VN3 or Goal completion; final installed full-story/preparation integration remains.
