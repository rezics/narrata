# REZICS 接入 Goal 交接简报

更新：2026-10-30。首发 Gamingbook 是正文阅读与分支选择；传统 Web VN 随后纳入。
本页根据[重建宿主的能力复核](rezics.md)更新，供 REZICS 按当前工作流程建立接入任务。
Narrata 不修改 REZICS 仓库，也不在自己的 goalctl 中登记或派发 REZICS worker。

## 结果与边界

在 REZICS 中提供完整的互动小说创作、发布和阅读流程，消费 Narrata 的带版本 npm/Wasm 包。
正文、译本、选项文字、权限与审核、作品内容组织、网站路由和用户存档同步属于 REZICS；叙事运行、
存档语义、通用宿主接口和图分析属于 Narrata。REZICS 特有的解析与网站适配器由本 Goal 实现。

先核对[七项首发能力及旧 R1–R13 对应](rezics.md#能力请求)、[ADR 0021–0023](../adr/) 和实际代码，记录接受、已有、需要调整或未实施的
能力及理由。Occurrence、Expression、Structure 和旧表布局不是重建宿主已经实现的前提。
接口差异通过能力请求与 Narrata 对齐；不直接修改 Narrata 仓库。

## Narrata 交付里程碑

[当前 Narrata Goal](../goals/web-and-rezics/GOAL.md) 的 M1 提供首发可安装包；REZICS 可从该版本开始接入和核对边界，完整阶段的图、演化和维护按 M2 后续包验证。每次接入只使用实际交付的公开能力，不把 ADR 或未合入分支当作现成 API。M3 提供发行与交接证据；双方最终以同一固定版本执行真实联合旅程。

[后续 Web VN](../goals/web-vn/GOAL.md) 的规划已记录，尚未启动；需要的媒体和分发能力见集成文档，不与首发正文/选择型 Gamebook 混为同一阅读体验。

## 任务顺序

REZICS manager 可按下面顺序实施。先对 M1 首发能力做真实联合验收，M2 的图、演化和维护随后增量接入、另行验收；多译本只在启用时验收完整作者流程。

1. **接口对齐与能力确认。** 核对稳定内容单元 key 到当前文档修订的映射、块 ID、选择标记、
   选项标签、批量解析、内容大纲、构件加载和存档同步。取得 Narrata 接口类型及测试样例，明确
   版本与错误结果；M1 公共创作/发布、在线生命周期与构件寻址恢复已完成本地固定包验收，按[固定输入](rezics.md#narrata-自己的交付依赖)开展真实接入。地图、visits、稀疏关系及有界 SQL SDK 已通过固定包验收；按[地图与关系接入](rezics.md#地图与关系接入)核对宿主责任，使用地图增量的固定输入。维护及完整阅读器迁移组合仍待后续交付，M2 尚未完成。
2. **内容与编辑。** 实现正文/标签解析、标记块与大纲；接入草稿、编辑与私有预览，保留语言/译本上下文。
   沿用 REZICS 的权限和生命周期，解析结果符合 `ok`/`unavailable`/`incompatible`。
3. **发布与存放。** 将已校验的 Narrata 不可变构件存入对象存储，提供按需读取，完整就绪后
   比较并切换当前可玩发布；旧会话继续加载自己的构件。正文与媒体
   继续遵守宿主当前授权和撤回政策，不因保留无正文程序而承诺永久保留内容。
4. **网站阅读与存档。** 路由懒加载发行包，正文通过 REZICS 的渲染组件接入；完成选项、路径、
   结局及按用户隔离的存档协议、并发、幂等与同步；使用已有快照导出和恢复接口。Library
   progress 只作为存档确认后的继续阅读投影，不替代 Narrata 执行状态。
5. **M1 首发真实联合验收。** 前四项完成后，在 REZICS 安装固定 Narrata 包，执行创作、私有预览、
   发布 A、读者保存、发布 B、旧会话恢复 A/新会话进入 B，以及失败恢复的旅程，留存证据。
6. **M2 扩展接入与验收。** 使用地图增量固定输入，接入作者图、关系投影及 visits/读者地图；显式安装包内 DDL，提供原生 null/boolean SQL 参数、受授权的事务与有界查询，分别验证作者与读者权限。保留精确构件、祖先及受信迁移证据，地图仅在读者请求时加载，不能将客户端访问记录用作权益或奖励证明。作品演化和维护（包括有界冷库导入导出、浅历史及 GC）随后续交付逐项验证；启用多译本时补标签联动、稳定块对应和缺译回退。完整接入 Goal 可在这些结果完成后关闭。

## 固定版本的输入与验收

输入必须能在另一台电脑复现：明确的 npm 包版本（alpha 或其他预发行版本也可）、源码提交、
包校验和、Wasm 资源、公开类型、接入说明与样例。不使用 `latest`、兄弟仓库链接或未发行的源码
替代品。M1 历史固定输入不包含后续地图增量；地图增量使用集成文档中另列的源码与包校验和。npm registry 尚未发布，真实 REZICS 联合验收尚未执行，能力请求仍为“提出”。可以消费 registry 版本，或双方确认的同版本 npm tarball；记录实际使用的交付物。

M1 验证创作到发布、首次加载与预取、局部/分支及多选、权限或内容撤回、刷新恢复、分支切换、
快照导出/恢复、跨设备同步及并发冲突。M2 另验图视图、剧透边界、演化、有界冷库导入导出、浅历史与维护，多译本启用时再验译本与标签联动。
结合 REZICS 自身的检查、真实浏览器操作和双方既定加载预算，分别记录每个里程碑的 REZICS 提交、
Narrata 版本、环境、通过项与剩余问题。后续 Web VN 按[对应联合旅程](rezics.md#web-vn-真实联合验收)另验。

发现 REZICS 缺陷由本 manager 修复；发现 Narrata 缺陷交回 Narrata manager，后者修复并产生新版本，
本 Goal 锁定新版本重新验证。最终没有阻断性问题时，REZICS manager 才关闭本 Goal。
Narrata SDK 的模拟宿主验收与版本交付可先完成，不以本 Goal 的完成作为关闭前提。
