# 编号决定

本页记录比单个 Goal 更长寿的产品与架构决定及其理由。决定可以被维护者或后续决定修改；
修改时追加新编号并在旧条目注明被谁取代，不删除历史。线格式与冻结语料层面的细节仍写入
[ADR](../adr/)。

证据主要来自两轮调研：
[叙事引擎核心与可插拔存储](../research/2026-10-04-engine-core-and-storage/report.md)（2026-10-04）
和 [选项粒度与规模](../research/2026-10-05-choice-granularity-and-scale/)（2026-10-05）。

## 1. Narrata 是通用叙事引擎

2026-10-05。Narrata 的长期目标是让复杂叙事变得容易。首个宿主是 REZICS 的互动小说，
第二个首要场景是本地游戏；接口不为 REZICS 特化。
见 [目标](goal.md)。

## 2. 内核不含正文

2026-10-05。Narrata 维护节点、关系、状态与历史；正文、选项文字、标题和媒体都由内容方
提供，Narrata 只保存内容引用。文本不进入逻辑构件身份，也不进入状态摘要和 Snapshot。

理由：内容可以持续增加或修订而不影响时间旅行和存档；本地化、审核与授权留在内容方；
叙事学的 fabula/narration 分层、BBC 对象化媒体和 Yarn 字符串表都支持运行时分离。
创作时文字与逻辑可以并置，编译时分离。会影响规则判断的内容（谜题答案、需要比对的名字）
不是"内容"，属于程序本身。

当前实现与此冲突：`ProgramArtifactId` 和 Snapshot 都包含文本，节点运行时硬编码了结局文字。
迁移需要新的格式 ADR 与新冻结语料（见决定 14）。

## 3. 身份以 Narrata 为权威

2026-10-05。节点、选择点、选项和边的 ID 由 Narrata（编译器、创作工具或接受动态提议的
运行时）铸造，使用 [ADR 0002](../adr/0002-identities-and-digests.md) 的 16 字节作者身份，
默认填 UUIDv7。可读 key（如 `help`）是作者别名，可以改名；身份不变。ID 不由任何数据库
生成，内容方的 ID 只作为引用。

| 操作 | ID |
| --- | --- |
| 改文字引用、条件、效果、顺序 | 不变 |
| 改目标节点 | 不变；旧存档差异由重放分歧检测与迁移处理 |
| 移到另一个选择点 | 新 ID |
| 复制 | 新 ID |
| 删除 | 留墓碑，永不复用；旧存档解析得到明确的"已删除" |

理由：本地游戏、离线创作和多人并发创建都不能依赖往返数据库领号；ID 需要跨作品、跨环境
复制和导入。

## 4. 内容引用协议与内容方无关

2026-10-05。内容引用由内容方标识、内容方自定义的不透明 key 和可选锚点组成。解析由宿主
批量执行，结果只有 `ok`、`unavailable`（不存在、无权限、已撤回、已擦除合并为一种，不泄露
原因）和 `incompatible`。解析上下文包含语言偏好和所选译本。引擎为每次呈现提供稳定的
呈现键（执行、提交、节点出现），生成式内容方据此缓存，回到同一提交得到同一段文字。
恢复存档从不依赖旧内容仍可解析。见 [内容引用契约](../contracts/content-references.md)。

## 5. 两类选择，正文不嵌套选择树

2026-10-05。选项的结果分两类：**局部结果**在同一内容单元内显示回应块并汇合，只改变状态；
**分支结果**进入另一个节点。一个选择点可以单选或多选（最少、最多选择数）。正文文档是扁平
的块序列，最多只含一个记录选择点 ID 的标记块；选项集合、条件、效果和去向都在 Narrata。
选项文字是内容引用，按与正文相同的解析上下文解析，因此跟随读者所选的译本。

理由：多数选择是几行后就汇合的小选择（对 Choices 六部作品的统计约 22 个选择/章，只有约
3% 通向独立路线）。若每个选择都进入新内容单元，10 万选择点需要约 34 万到 55 万个单元；
ink 的 weave、ChoiceScript、Yarn、Ren'Py、易次元和橙光都加入了单元内汇合的选择。
见 [选择模型契约](../contracts/choices.md) 与
[粒度调研](../research/2026-10-05-choice-granularity-and-scale/choice_granularity.md)。

## 6. 会改变走向的动态内容是输入

2026-10-05。生成式系统提出的新选项、新节点或新事实，经引擎校验后作为输入写进提交历史；
回退和重放使用记录的结构，不重新生成。只影响呈现的生成文字只记录内容引用。

## 7. 存储分三种角色，运行时不查数据库

2026-10-05。作者源稿由宿主保存（REZICS 的 PostgreSQL、本地文件等）；编译后是不可变、
内容寻址、分块的构件；会话存档是对象与引用。运行时只读构件和存档，不查询宿主数据库。
图数据库不作为运行时存储；Narrata 可以导出语义摘要供宿主写入图库（REZICS 的 Jena）。

理由：Narrata 的运行时负载是浅读加追加写，属于 Git/Dolt 式对象库的工作负载；深度图查询
只在创作分析中出现，100k 节点在内存中毫秒级完成。见
[存储与存档契约](../contracts/storage-and-saves.md)。

## 8. 存储契约保持窄

2026-10-05。后端只需提供：按摘要读写不可变对象、带修订号的引用比较并交换、原子批次、
有序且有界的扫描，以及能力声明。效果账本、目录、GC、完整性检查与迁移在契约之上只实现
一次。Narrata 维护的后端：内存（行为参考）、SQLite（本地与工具）、浏览器 IndexedDB，以及
交给宿主保存的存档字节。服务器数据库由宿主在自己一侧使用存档字节，不进入 Narrata 运行时。

## 9. 两个首要运行环境

2026-10-05。网站使用 Wasm 运行时，按路由懒加载；本地游戏使用原生库，存档以字节交给宿主
自己的存档系统。两者使用同一内容包格式，网站按需拉取程序块，本地同步读取。

## 10. 规模来自分块

2026-10-05。单部作品以 10 万选择点为设计目标。程序按包和块切分并按需加载，读者端峰值内存
与活跃块数成正比；去掉现有节点栈 4,096 节点、4 MiB 的整包上限。以合成作品基准验证。
宿主可以按自身当前规模接入。

## 11. 节点组合模型是长期内核的语义基础

2026-10-05。以节点组合模型（`packages/narrata/nodes`）作为长期的语义与创作基础。Stage 1–5
栈中的可靠执行机制——身份与摘要、确定性 CBOR、受检解码、提交/引用对象库、Effect 账本、
迁移与跨语言协议——抽取为 kernel，并泛化到节点实例状态。Flow VM 与 Statechart 成为第一方
领域包。旧格式通过适配器与冻结语料保持可读；不再在 `RuntimeStateV0` 上增加新的产品能力。

理由：[重建提案](../../archive/2026-09-05-rebuild-proposal.md) 已把节点组合定为语义基础，
而大部分验证资产（冻结语料、故障注入、迁移、绑定）在旧栈；两栈目前既不共享存储也不共享
身份，继续分叉会让每项新能力做两遍。

## 12. 图视图预先计算并分层交付

2026-10-05。发布时在 Rust 中完成拓扑分析（可达性、死路、结局、环、瓶颈）与按簇的分层
布局，按"作品 → 内容单元 → 单元内"分层、分块交付。作者视图用 WebGL 渲染器并限制同时
绘制的节点数；读者地图由服务端按读者走过的路径生成，不下发未揭示的节点。
见 [图与分析契约](../contracts/graph-and-analysis.md)。

## 13. 不修改 REZICS，需求写进集成文档

2026-10-05。Narrata 的工作不修改 REZICS 仓库。REZICS 需要增加的能力作为能力请求记录在
[REZICS 集成](../integrations/rezics.md)，由 REZICS 自己的 Goal 决定是否以及如何实施。

## 14. 兼容纪律

2026-10-05，重申 ADR 0003、0006、0009。`fixtures/compat` 下的冻结语料是只读证据；任何
线格式变化都需要新 ADR 和新冻结语料，并提供旧格式的读取或迁移路径。确定性与受检解码
不在没有 ADR 的情况下放宽。
