# Narrata 的目标

日期：2026-10-05。本页说明 Narrata 要成为什么，比任何单个 Goal 都长寿；具体取舍见
[编号决定](decisions.md)，当前工作见 [GOAL.md](../../GOAL.md)。

## 结果

**Narrata 是通用叙事引擎，目标是让复杂叙事变得容易。**

作者用它描述节点、选择、状态与后果；引擎负责确定性执行、存档、时间旅行、迁移和分析；
正文、选项文字、图像、声音等真实内容由内容方提供。同一部作品可以在网站、本地游戏和
生成式（AI）体验中运行，内容可以持续增加，而已有存档和时间线不被破坏。

## 首要场景

| 场景 | 宿主 | Narrata 交付什么 | 存档在哪里 |
| --- | --- | --- | --- |
| 网站互动小说 | REZICS（首个宿主）或其他 Web 产品 | Wasm 运行时与 TypeScript 包、阅读器外壳（正文通过渲染插槽交还宿主）、图视图 | 浏览器 IndexedDB；登录用户由宿主同步到服务器 |
| 本地游戏 | Unity、Godot、Bevy、自研引擎 | 原生库与 C/C#/Rust 绑定、内容包加载、存档字节 | 宿主自己的存档系统（Steam Cloud、主机平台存档 API 等） |
| 生成式叙事 | AI 游戏、动态内容服务 | 结构与状态权威、动态节点与选项、呈现键 | 同上；生成结果由内容方按呈现键缓存 |

REZICS 是第一个落地宿主，但 Narrata 不只服务 REZICS：所有接口都与内容方无关，REZICS
只是其中一个内容方和宿主。

## 原则

1. **结构归引擎，内容归内容方。** Narrata 保存节点、选择、状态、历史和对内容的引用，
   不保存正文。内容的本地化、审核、授权和生命周期由内容方负责。
2. **确定性优先。** 相同的构件、状态和输入得到相同的结果；任何会影响走向的外部结果都作为
   输入记录下来，回放与时间旅行不依赖重新调用外部服务。
3. **存档跨版本存活。** 稳定身份、墓碑、显式迁移和重放分歧检测让作品在发布后继续演化。
4. **规模来自分块与身份，不来自数据库。** 运行时只读不可变构件，按需加载，峰值内存与
   活跃部分成正比。
5. **复杂度由引擎和第一方能力承担。** 作者使用默认套件即可写 Gamebook、互动小说和对话；
   需要时再替换能力或策略。

## 规模目标

- 单部作品 10 万个选择点。以局部选择为主时约为数千个内容单元（见
  [选择粒度调研](../research/2026-10-05-choice-granularity-and-scale/choice_granularity.md)）。
- 读者端峰值内存与当前活跃的程序块数成正比，而不是与作品总量成正比。
- 本地游戏中每次选择的引擎处理时间以毫秒以下为目标；网页首屏只下载清单与首个程序块。

这些数字是设计目标，由合成作品基准验证并在基准结果出来后修订。宿主可以有更小的当前
规模：REZICS 按其现有量级接入，不为 30 万章节做准备。

## 非目标

- 不做正文编辑器、内容管理、本地化平台或媒体制作管线；它们是其他产品。
- 不在运行时查询任何数据库，也不把图数据库当作运行时存储。
- 不承诺通用的 exactly-once 外部副作用；宿主提供幂等键、事务接口或显式未知结果处理
  （见 [Effect 与宿主状态](../architecture/effects-and-host-state.md)）。

## 路线

1. 内核去文本、内容引用协议与选择模型（Goal `narrative-core`）。
2. 可靠执行机制收敛为 kernel，窄存储契约与可移植存档（Goal `kernel-and-saves`）。
3. Web 包、阅读器外壳、图视图与 REZICS 适配（Goal `web-and-rezics`）。
4. 之后：VN/Scene 类型、同伴与社会关系、任务、作者工作台，按
   [重建提案](../../archive/2026-09-05-rebuild-proposal.md) 的 R2–R4 方向推进。
